# 公共 Agent 默认规则

## 测试与验证

- 验证产品行为时，用本次构建从真实入口走完整用户流程，使用真实应用、账号、权限、依赖、数据和会话状态，并核对最终页面或业务结果。自动化只能代替人工操作，不能绕过这条链路。
- 单元或集成测试、Mock、直接调用接口、编译和扫描等，只能说明各自的检查结果，不能算真实端到端测试。真实流程没跑完，就明确说明哪些没测、哪些没覆盖。

## 产出代码时

- Agent 新产出的脚本默认使用 Python，文本读写显式使用 UTF-8。该规则只约束新脚本的实现语言，不改变已有程序或启动方式；已有 Java/JAR 按原入口直接执行。

- 遵守当前项目已启用的产出规则，用最少的代码完成功能，除此之外不要增加任何代码、结构或抽象。

## 执行控制

- 用户明确要求“不要停”“一次跑完”或同义表述时，只要后续操作仍在当前授权范围内且不需要用户决定，就持续执行到完成，不再询问是否继续。
- 完成一个步骤后，只要下一步仍属于当前任务且不需要用户决定，就直接继续；不得因为步骤较多或阶段发生变化而暂停。
- 遇到难以恢复的删除或覆盖、需要扩大任务范围、当前规则互相冲突，或缺少只有用户知道的信息时，暂停相关操作并请用户决定或补充。
- 暂停时，开头直接说明哪项操作尚未执行、卡在哪里，以及用户需要决定或提供什么。

## 回复与反馈

- 回复先说结论，不先铺陈过程。
- 需要用户确认、Review 或补充信息时，在开头直接说明需要用户决定或提供什么。
- 用户只要求分析或说明时，明确本轮没有修改文件、没有执行操作。不得用“建议执行”“建议删除”等说法模糊到底由谁操作、是否已经完成。

## 文件读不到或规则冲突时

- 当前任务必须读取的文件不存在或打不开时，说明具体文件以及因此不能继续的操作。
- 两个当前文件的要求互相矛盾时，停止发生冲突的操作，并请用户确认采用哪一条。
- 不要拿旧文件、模板、Agent 自己的猜测或 Git 历史版本代替当前文件。
