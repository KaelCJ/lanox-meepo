# SKILL.md 正文审计

审计用户给出绝对路径的 SKILL.md 的 Markdown 正文。审计依据分两个效力层级，结论必须标注层级：

- **规范层**（agentskills.io Specification，违反计「违规」）：
  1. 体量：正文超过 500 行即为违规（规范原文 "Keep your main SKILL.md under 500 lines"）；超过 5000 tokens 计为「建议」（原文措辞为 recommended）。行数精确统计，token 报告估算值并注明估算方式。
  2. 引用捆绑文件必须使用相对路径、保持一层深、避免嵌套引用链。
  3. 引用必须写明加载时机；「详见 references/」这类无时机声明计为违规。
  4. 推荐章节（分步指令、输入/输出示例、常见边界）缺失只计「建议」，不计违规。
- **方法论层**（官方 Best practices，违反计「建议」）：
  1. 逐条增删判据：解释 agent 已知的常识（PDF 是什么、HTTP 怎么工作）计为建议删除。
  2. 范围连贯性：一个 Skill 承载多个不连贯工作单元时计为建议拆分。
  3. 控制力校准：脆弱操作未给精确命令、或灵活任务过度逐步规定，均计为建议。
  4. 菜单式罗列无默认选择计为建议。
  5. 答案式内容（只对本次实例有效、不可复用）计为建议改写；输出格式模板与硬边界声明属于合法例外。
  6. 缺少 Gotchas 类环境事实节只计观察，不计问题。

## 审计方法

1. 读取目标文件；读不到时如实报告并停止。
2. 统计正文行数（frontmatter 计入文件但单独标注），估算 token 并注明估算方式。
3. 提取正文引用的全部捆绑文件路径：核对文件存在性、相对层级深度、加载时机声明。
4. 逐节过方法论六条；每条问题给出位置（行号或节标题）与最小原文摘录。
5. 结论分级：违规（规范层）/ 建议（方法论层）/ 合规保持；同族分工问题（应由 Skill/Rule 承载的内容）单独归类。

## 输出

- 第一行总体判断（该 SKILL.md 正文是否合规、主要问题类型）。
- 问题清单：位置、效力层级、问题、建议（删除 / 改写 / 拆分 / 迁移）；只列问题，不重写全文。
- 报告明确写出未验证边界：token 为估算值，规范层的加载时机判定基于正文声明而非运行行为。
