# Nest Git 提交

暂存当前空间的全部可提交变更，然后把暂存区作为一次干净的本地提交。调用语义等同在项目根目录右键 → Git Add：`git add -A`，它会暂存所有修改、新增和删除的文件，并已自动拒绝 `.gitignore` 匹配的文件。这个 Skill 补足暂存点击没做的事：仓库要求的校验、符合仓库风格的提交信息，以及一次不越过暂存区快照的提交。

## 硬性规则

- 将显式的 `$nest-git-commit` 调用视为授权：执行 `git add -A` 暂存当前空间、执行要求的校验，并把暂存后的索引在本地提交，无需例行再次确认。如果用户要求仅预览或不要提交，则在审阅后停止，保持索引不变。
- 只通过 `git add -A` 暂存当前空间。绝不允许裸 `git add`、`git add -- <路径>`、`git add -u` 或交互式 add。
- `.gitignore` 是唯一的暂存过滤条件：`git add` 本身已拒绝被忽略的文件，因此本 Skill 不做任何垃圾、二进制或密钥方面的额外筛查。
- 暂存后的索引就是提交范围，包含用户调用本 Skill 前已手工暂存的内容（IDEA 的提交对话框行为相同）。`git diff --cached --name-status` 定义将被提交的内容。
- 在校验或提交前，读取当前宿主的仓库指令链以获取要求的校验入口和提交信息风格；若其已完整且最新则直接复用。
- 绝不推送、不创建 PR、不改写历史、不 reset、不 rebase、不删除分支、不绕过钩子。不要为了通过校验而修改源码或内容。

## 检查

```powershell
git status --short --branch
git log --format="%h %s" -10
```

仓库没有提交时省略日志。

- 先执行 `git add -A` 暂存当前空间。
- 然后 `git diff --cached --name-status` 就是提交范围；仅在撰写准确提交信息需要时分路径读取 `git diff --cached -- "<路径>"`。
- 暂存后索引仍为空：报告没有可提交内容并停止。
- add 之后剩余的未暂存变更不属于本次提交；在报告中注明这类漂移。
- 从近期日志归纳提交信息风格与 scope 词汇。

## 校验

- 仓库声明了校验入口时使用它。当文档写明提交钩子是认可的入口时，依赖钩子并在报告中说明该选择，绝不重复执行或绕过钩子。
- 否则使用项目隐含的最小可靠构建或检查命令；没有文档化命令时使用轻量检查；纯文档变更可跳过校验——并在报告中说明。
- 失败时报告失败并停止；不要改源码强行通过，也不要制造失败的检查点。
- 校验针对工作区运行，其中可能包含未暂存变更；校验通过不代表暂存快照单独通过。当这种差异要紧时，明确说明实际验证了什么。

## 提交

用 `git diff --cached --name-status` 确认索引仍等于已审阅的范围，然后提交：

```powershell
git commit -m "<message>"
```

整个暂存区一次提交。如果明显横跨多个不相关主题，也用一条诚实覆盖全部内容的提交信息提交并在报告中说明；拆分由用户决定——重新暂存后再次调用本 Skill。

使用仓库现有的提交信息风格；仅当日志本身已采用 Conventional Commit 形式时才使用它。复用日志中已有的 scope 词汇而不是自创 scope，没有合适的就省略 scope。避免 `update`、`整理`、`fix stuff`、`worktree cleanup` 这类含糊信息。

## 报告

```powershell
git status --short --branch
git log --oneline --decorate -3
```

报告实际执行的暂存命令（`git add -A`）及其暂存内容、提交哈希与提交信息、提交包含的内容、校验命令及其决定性输出（原样粘贴而非转述），以及明确的未做事项：未推送、未改写历史、未提交暂存区之外的任何内容。
