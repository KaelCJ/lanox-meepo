# Workspace 采用审计

## 目标

先理解目标空间，再判断它与当前来源 Workspace 公共资产的关系，给 Human 一个能够直接决定“保持现状、自己同步或一键同步”的报告。

本 Skill 负责理解和判断，不自行实现文件复制。机械比较和写入由 `$nest-workspace-sync` 及其脚本负责。

## 模式与授权

- 用户要求审计、检查版本或给建议：只读，不修改目标。
- 用户要求自己同步或手工步骤：只读，输出具体差异和步骤。
- 用户明确要求同步、一键同步、按建议同步或审计并同步：完成审计后调用 `$nest-workspace-sync`。
- 一键同步授权只覆盖 `$nest-workspace-sync` 的受管白名单，不包含业务代码、项目专属入口、Git 提交、发布或外部操作。

目标路径必须由 Human 明确给出。路径缺失、不是既有绝对目录、指向来源自身或来源上下级、文件系统根、链接、junction 或其他 reparse point 时停止。

## 理解目标空间

按目标实际存在内容读取：

- 根及相关目录的 `AGENTS.md`、`CLAUDE.md`；
- README、项目结构和主要模块；
- `.workspace-assistant/10-工作项/` 及权威索引；
- `.workspace-assistant/foundation/`；
- `.agents/skills/`、`.claude/commands/`、`.codex/`；
- 当前 Git 状态，特别是受管路径上的未提交修改。

形成最小目标模型：

- 项目是什么，当前怎样组织 Human 与 Agent 协作；
- 哪些是项目专属事实，不能由公共同步覆盖；
- 当前有哪些公共资产和协作接线；
- 受管资产是否存在本地定制或冲突；
- 目标是否具备同步后登记本地工作项的治理入口。

理解目标只服务于 Workspace 采用和同步判断，不自动扩展为业务代码、安全、Java 或文本全面审计。

## 机械比较

加载 `$nest-workspace-sync`，使用其脚本只读检查：

```text
python -X utf8 "<当前来源绝对路径>\.agents\skills\nest-workspace-sync\scripts\sync_workspace.py" --check --target "<目标目录绝对路径>"
```

把脚本结果作为机械证据，而不是完整审计结论。报告必须写明实际来源绝对路径，核对 `skillInventory.source`、`target`、`missing`、`extra` 及数量；本仓库目前有 18 个 `nest-*` Skill（具体名称见 `$nest-workspace-sync` 的“唯一受管范围”），审计其他来源时以其实际 Skill 清单为准，不得只检查或同步其中两个。

只有当前 Session 明确位于权威 `nest-agent` 空间时，才能把比较来源称为“当前 nest-agent 空间”；从其他已同步空间运行时，只能说“相对当前来源受管资产”。不要从文件差异推断未经证实的发布版本。

## 状态解释

- `CURRENT`：目标受管资产与当前来源完全一致。
- `NOT_ADOPTED`：目标当前没有受管资产。
- `PARTIAL`：目标有受管资产，但缺少来源的部分条目。
- `DIFFERENT`：目标不缺来源条目，但受管内容或目标多余条目有差异。
- `UNKNOWN`：目标无法安全读取或证据不足。

这些状态只描述当前内容差异，不自动推断“版本过旧”或“本地修改”。结合目标 Git 状态和文件所有权另行识别需要保留的定制；没有历史证据时，不把 `NOT_ADOPTED` 写成“历史上从未同步过”。

## 协作接线检查

结合目标事实判断：

- Nest SessionStart Hook 是否存在并指向可用基座；
- `nest-*` Skills 和 Claude Commands 是否完整；
- Codex Git 规则是否存在；
- 目标根入口是否保留项目专属事实，而不是公共入口副本；
- 目标工作项入口是否可用；
- 公共资产和目标本地资产是否混在错误所有者中；
- 脚本计划删除或覆盖的内容是否包含需要 Human 保留的本地修改。

不要求每个目标具有相同的根 README 或 AGENTS 正文；它们本来就属于目标项目。

## 同步建议

报告必须把建议分成三组：

1. **可自动同步**：完全位于 `$nest-workspace-sync` 白名单，且没有未解决本地冲突。
2. **需要 Human 决定**：受管路径本地修改、来源删除但目标仍在使用的能力、无法判断所有权的内容。
3. **项目自行适配**：根入口、README、业务事实和其他不属于公共同步范围的内容。

用户选择自己同步时，给出新增、覆盖、删除、保留、冲突、备份和复查步骤，不写目标。

## 一键同步

用户已经明确授权时：

1. 在执行前重新运行只读检查，不能使用过期差异。
2. 目标受管路径存在未提交的本地修改或无法解释的定制冲突时，没有 Human 处理决定就停止写入并列出具体文件；普通内容差异按同步授权继续。
3. 加载 `$nest-workspace-sync`，按其规则执行备份、全量同步、逐文件对账和目标工作项登记。
4. 同步后重新运行本 Skill 的机械比较和协作接线检查。
5. 只有机械状态为 `CURRENT`，且 `skillInventory.source` 和 `target` 名称与数量逐项一致、`missing` 和 `extra` 均为空时，才能报告全部公共资产同步完成。
6. 项目专属入口仍有适配建议时，单独列出，不把它混入公共同步成功结论。

## 报告格式

先给结论，再给差异和动作：

```text
目标空间
比较来源绝对路径
当前状态
来源与目标 Skill 清单及缺失项
协作接线
文件差异摘要
目标本地修改
可自动同步
需要 Human 决定
项目自行适配
建议的下一步
已执行动作与未验证边界
```

没有运行同步时明确写“本次只读，目标未修改”。运行同步时报告备份位置、实际新增/覆盖/删除、对账结果和同步后状态。
