# Workspace 采用审计

## 目标与边界

先理解目标空间，再依据当前可读的来源和目标文件，判断协作资产的采用、接线及本地差异。只报告能够核实的文件事实；没有权威发布证据时，不声称目标是最新版本或与某个发布完全一致。

全程只读：不复制、覆盖、删除、备份或登记工作项，不执行 Hook 或 JAR，也不修改 Git index。用户要求审计并同步或一键同步时，只提供差异和人工适配建议，说明本 Skill 不执行同步；需要写入时另行明确目标、范围和处理方式。

目标路径必须由 Human 明确给出。路径缺失、不是既有绝对目录、指向来源自身或来源上下级、文件系统根、链接、junction 或其他 reparse point 时停止。

## 理解目标空间

按目标实际存在内容读取：

- 根及相关目录的 `AGENTS.md`、`CLAUDE.md`；
- README、项目结构和主要模块；
- `.workspace-assistant/10-工作项/` 的索引结构和入口；
- `.workspace-assistant/foundation/` 的已存在资产和接线；
- `.agents/skills/`、`.claude/commands/`、`.codex/`；
- 当前 Git 状态，特别是相关路径上的未提交修改。

区分项目专属事实、公共 Skill/Command、宿主 Hook 与待授权资产。只按本次审计需要读取工作项元数据，不把真实工作项或 Session 内容复制到报告。理解目标不自动扩展为业务代码、安全、Java 或文本全面审计。

## 文件与接线核对

记录比较来源的实际绝对路径和可核实的版本线索。对目标已采用的文件，按路径、内容差异或哈希进行只读比较；列出无法读取、明确排除和未确认的范围。单个文件相同只证明这份文件与该来源快照一致，不证明全部规则已由宿主加载，也不证明目标采用最新发布。

结合目标事实检查：

- `AGENTS.md` / `CLAUDE.md` 的入口角色和目标项目专属约束；
- 已存在的 `nest-*` Skills、Claude Commands 与 Codex 规则；
- SessionStart Hook 的配置路径、依赖和授权状态，不执行 Hook 或二进制；
- 工作项索引是否齐全及其入口是否可定位，不自动初始化或修复；
- 本地修改、缺失资产及来源与目标的职责边界。

不要求目标根 README 或 AGENTS 正文与来源相同；它们属于目标项目。旧的发布指纹和自动同步状态不再构成审计依据。

## 判断与建议

- **已采用**：指定范围的关键入口和协作资产可定位；分别报告已检查文件与仍未确认的接线。
- **部分采用**：只存在部分入口或协作资产，或者配置引用的依赖缺失。
- **未观察到采用**：本次检查范围内未发现相关资产；不据此断言目标历史上从未采用。
- **无法确认**：权限、路径或证据不足，保留已核实的部分并说明缺口。

把建议分为“可手工核对的文件差异”“需 Human 决定的本地修改或授权问题”“项目自行适配的入口与事实”。若用户请求手工迁移步骤，先指出需备份和复查的具体范围；不要把建议当成已经执行的同步结果。

## 报告格式

先给结论，再报告：

```text
目标空间与比较来源
观察到的采用状态和检查范围
入口与宿主接线
文件差异及本地修改
需要 Human 决定的事项
项目自行适配的事项
建议的下一步
未验证边界
```

末尾明确写“本次只读，目标未修改”；若没有发布证据，明确说明未验证最新版本或真实宿主生效情况。
