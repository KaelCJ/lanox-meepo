# Session 归档

## 所有权与边界

本 Skill 是归档语义的唯一入口，负责：

- 当前 Session 的事实盘点与唯一工作项映射；
- 用户决定、当前事实、历史结论、工程债和未来候选的分类；
- 当前需求、方案、执行、验证和 README 的认知收敛；
- 当前 Session 收敛结果的无聊天上下文恢复检查，包括最小恢复路径、聊天残留与后续接手就绪度；
- 过时竞争入口的退出；
- 退场材料的物理删除或集中隔离；
- 明确闭环工作项的整体归档、取消归档和归档恢复；
- `current.json` / `archive.json`、导航、引用和恢复入口的对账。

`nest-work-item` 的创建与按需参考方法不构成本 Skill 的归档流程。归档、历史退场和归档恢复以本 Skill 的边界为准。

本 Skill 不自动：创建工作项、创建或切换宿主 Session、选择融合归属、改变既有用户决定、提交、发布、发送、部署、操作真实业务数据、归档宿主 Session，或删除无法证明可恢复边界的整项工作项。

## 触发与授权

- 只有用户显式调用 `$nest-session-archive`、明确点名本 Skill，或明确要求执行归档检查/认知收敛/历史退场/取消归档/归档恢复时才开始。
- 显式调用授权：盘点当前 Session；补记唯一归属的已有工作项；收敛当前入口；验收当前收敛结果能否仅从最小权威入口被无聊天上下文恢复；移除当前导航中的过时竞争入口；按下述规则删除明确无价值的退场材料或集中退场；对明确闭环且无冲突的工作项执行可恢复整体归档。
- 新建工作项、无唯一归属时的融合、多个归属、语义冲突、改变既有决定，以及不可逆删除整项工作项，必须停在 Review。
- “完成”不自动推出“可归档”；“暂不整体归档”也不等于本轮没有完成认知收敛或历史退场。

## 阶段一：窄映射

1. 只盘点当前 Session 涉及的主题，不扫描全部工作项制造待办。
2. 以用户决定、当前文件、工具结果和实际运行事实为证据，不按最近编号、分支或改动路径猜归属。
3. 直接从采用环境的 `current.json` 与 `archive.json` 窄查当前主题；只读取识别唯一归属所需的记录，不要求根入口声明查询命令。可复用 `nest-work-item/scripts/work_item_index.py` 的 `resolve`、`find` 和 `candidates`，但不得借查询命令创建工作项。
4. 只读取命中项、引用计数、候选入口及其直接导航证据；分类为唯一已有归属、无归属、多归属或语义冲突。
5. 映射未成立时只报告建议新建、建议融合到具体候选或无需工作项，不写入任何工作项。

## 阶段二：认知分类

把本 Session 的新信息分成以下六类，并为每类保留来源、时间和替代关系：

| 类别 | 处理方式 |
|---|---|
| 最新用户决定 | 作为当前有效输入，追加来源并传播到真实受影响入口 |
| 当前已核实事实 | 记录事实所有者、核对范围和不能推出的结论 |
| 被替代的历史结论 | 保留来源关系，退出当前入口，不再作为当前依据 |
| 工程债或已知缺口 | 保留为当前边界或风险，不得无故阻塞主线 |
| 未来候选或可能抽象 | 留在未来候选，不提前进入当前方案或执行 |
| 待用户决定 | 停止受影响写入，形成精确 Review 问题 |

原始来源追加保存，不覆盖旧来源；当前入口只呈现当前有效结论。不得把历史证据、工程债或未来候选写成当前要求。

## 阶段三：认知收敛

按实际影响修改唯一工作项中的权威入口：

1. 工作项 `README.md`：更新当前目标、边界、决定、结果、下一步和已有产物导航。
2. 已经存在且本次真实受影响的来源、需求、方案、执行或测试入口：更新唯一当前事实；不存在时不为收敛形式补建。
3. 只有跨文件消费者确实存在时才维护 `REQ`、`AC` 或 `StepID`；轻量工作项使用自然语言标题。
4. 被否决方案、旧执行路径和失效证据退出当前主线，同时保留必要来源、失败和替代关系。
5. 如果本次补记确实修改了某类正式产物，只按需查阅 `nest-work-item` 的对应参考；不为形式完整加载全部方法。

## 阶段四：后续 Session 无聊天上下文恢复验收

认知收敛后，用“下一名 Agent 不读取当前聊天正文”的标准验证当前 Session 的持久化结果能否被后续接手。这里检查的是当前工作项入口的可恢复性，不读取或扫描其他 Session，也不自动创建、切换、fork 或归档宿主 Session。

1. 从权威索引重新解析唯一工作项，先读取工作项 README，再只读其导航的当前入口和直接事实所有者；只有确有执行入口/步骤时才继续读取，不得用当前聊天记忆补足缺口。
2. 恢复验收要求仅据最小恢复集即可准确说出：当前工作项及是否仍在进行、当前对象与事实状态、活动项的唯一下一步及准确产出位置；已闭环或归档项则明确没有下一步并给出恢复入口。还应能说出动作边界与停止点、哪些历史入口只是待恢复或已退场、哪些外部动作尚未授权。
3. 将本 Session 的最新用户决定和已核实事实逐项反查到来源记录、当前入口或事实所有者。任何会改变对象、顺序、状态、资产资格、写入范围、完成判据或授权的内容若仍只存在于聊天中，判定为“暂不可切换”，先继续收敛；不靠交接摘要掩盖缺口。
4. 默认不创建单独的 Session 交接文档。若现有 README、执行入口和当前步骤已经构成唯一恢复路径，只在最终报告给出路径组成的“最小恢复集”；只有采用环境已有权威交接载体或用户明确要求时才写额外交接产物，且不得形成第二待办或状态真源。
5. 结论只能是：
   - `可切换`：唯一归属成立，活动事实已持久化；活动项的最小恢复集能推出唯一下一步和停止点，已闭环或归档项能明确无下一步及恢复入口；
   - `暂不可切换`：列出仍在聊天、冲突、失链或缺少事实所有者的准确内容，并在授权范围内先修复；
   - `需要另行新 Session 实测`：本轮只标记需验收，不创建或切换 Session；宿主真实加载或恢复行为只能由后续新 Session 验证，静态回读不能冒充实测。
6. 上下文过大可以成为“完成收敛后切换”的理由，不能成为跳过工作项补记、最小恢复检查或停止点的理由。

## 阶段五：历史物理退场

认知收敛后，逐项处理已退出当前入口的材料。当前工作项内只允许一个集中退场位置：

```text
<工作项根>/历史退场/
├─ 00-清理清单.md
└─ YYYY-MM-DD_<退场批次>/
   └─ 按原相对路径保存的材料
```

不得在 `需求/`、`方案/`、`执行/`、`测试/` 下各自散落历史目录；不得在当前 Markdown 末尾堆叠完整历史方案或废弃步骤。

对每个退场对象只能选择一个出口：

### 物理删除

仅当材料已经被当前权威入口完整吸收，且不含独有原话、用户决定、事实证据、失败证据、proof、外部契约或其他工作项仍在使用的来源，并且目标、引用和恢复边界均可精确核实时，才可删除。

删除前必须列出准确路径、内容性质、入站引用、替代入口和恢复方式；不可逆删除或无法证明恢复边界时停止并交给用户 Review。空目录和确认无引用的重复入口也必须按同一目标检查，不得用宽泛父目录或未解析变量删除。

### 集中退场

材料有证据价值、删除依据不足或需要等待后续清理时，移动到工作项根级 `历史退场/<退场批次>/`，保留原相对路径，并在 `00-清理清单.md` 记录：原路径、退场原因、替代依据、当前替代入口、保留价值、引用、允许清理条件和时间。

移动后原位置必须消失；禁止复制后两处并存。`历史退场/` 不是需求、方案、执行、测试或待办入口，当前导航不得继续指向其中的活动材料。

### 不处理

无法判断归属、引用、证据价值或用户意图时，保持原现场并报告缺口；不得用“已失效”标签掩盖判断失败。

## 阶段六：工作项整体归档

只有认知收敛完成，且目标工作项没有已知未完成目标、阻塞、待决定、验证缺口、归属冲突、活动引用冲突或未收口的退场材料时，才判断整体归档：

- 移动前核对唯一工作项目录、索引记录、README、归档目标和活动引用；
- 优先使用 `work_item_index.py archive` 可恢复地移动整个工作项目录，并把唯一记录从 `current.json` 移入 `archive.json`；README 随目录移动；
- 修复因层级变化失效的相对链接；
- 同步 `entry`、`updatedAt`、`archivedAt` 和活动导航；归档记录不增加 `status` 或 `location`；
- 重新核对唯一物理位置、索引入口、恢复入口和引用。

不满足条件时报告“认知已收敛，工作项继续进行”或“信息不足/待 Review”，不得仅因文件齐全、状态为完成或检查绿色而整体归档。

## 取消归档与中断恢复

- 取消归档只在用户明确要求时执行；恢复前检查目录冲突、替代关系、两份索引和当前活动入口，优先使用 `work_item_index.py unarchive` 同步目录、记录、`entry` 与 `updatedAt`。
- 归档移动中断时保留实际现场，报告原路径、临时路径、索引状态、剩余对象和人工恢复动作；不重建假成功。
- 发现的是整项删除中断现场时，保持实际现场并报告，不把删除恢复伪装成归档恢复。

## 阶段七：最终对账

至少重新核对：

- Session 事实 → 来源 → 实际受影响产物；
- README 与本项实际存在的需求、方案、执行、验证入口构成唯一当前主线；缺少不适用的职责文件不算缺陷；
- 旧计划、旧入口和退场材料已退出当前导航；
- 历史证据未被误删，退场材料没有原位与历史区双份；
- 活动项存在唯一下一步、准确对象、动作边界和停止点；已闭环或归档项明确无下一步及恢复入口；
- 最小恢复集无需当前聊天即可推出当前对象、事实状态、适用的下一步或无下一步结论、停止点和未授权动作；仍需真实新 Session 才能证明的宿主行为没有被静态检查冒充；
- `current.json` / `archive.json` 通过 `work_item_index.py validate`，文件归属、链接、物理位置和恢复入口一致；来源 ID、REQ、AC、STEP 只在已启用时核对。

没有补记、退场、归档、取消归档或恢复动作时，直接报告映射与证据边界。

## 报告

按以下顺序报告：Session 覆盖与主题；已补记项；已收敛入口；后续 Session 无聊天恢复就绪度、最小恢复集与仍在聊天中的缺口；已删除材料；已移入 `历史退场/` 的材料及清理条件；已整体归档项及恢复入口；跳过或失败原因；待 Review 选择；实际检查；未执行和未验证边界。

明确写出本轮没有执行的提交、发布、发送、部署、真实数据操作、宿主 Session 创建/切换/归档和未获授权的不可逆删除。
