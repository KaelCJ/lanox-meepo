# NJX-004 重复日志或内部细节外泄

## 元数据

- 状态：Ready
- 类型：Code Smell
- 质量属性：可靠性、安全性
- 默认级别：普通
- 标签：exception、logging、duplicate-log、information-disclosure
- 适用范围：异常日志、错误响应、用户提示和跨层传播链

## 为什么是问题

同一未处理异常沿多层重复记录会制造噪声和错误事件数量，只有 message 的日志又会丢失堆栈。把路径、SQL、上游响应或堆栈直接交给用户还会暴露内部实现或敏感事实。

敏感信息外泄或关键故障缺少完整堆栈时，实际级别提高为重大。

## 触发调查

- 底层记录 error 后继续上抛，或多个层级记录同一异常；
- 日志只记录异常类名或 message，没有完整 Throwable；
- 用户响应包含异常 message、堆栈、路径、SQL、内部标识或未脱敏上游响应。

## 判定所需证据

1. 还原同一异常从来源到最终入口的全部日志和响应动作；
2. 核对异常是否继续传播，以及哪一层真正拥有最终观测责任；
3. 核对入口是否记录一次完整且脱敏的 Throwable；
4. 识别用户可见内容中的内部或敏感事实及其具体暴露影响。

## 不应报告

- 已完全处理且不再传播的预期事件按契约记录了合适级别的日志；
- 不同层记录的是不同事件、不同状态转换或不同可操作上下文，而非同一异常的重复 error；
- 入口记录一次完整异常，并向用户返回独立、脱敏且符合协议的失败语义。

## 示例

不合规：Repository、Service 和 Advice 对同一异常各记录一次 error，Advice 又把底层 message 原样写入 HTTP 响应。

合规：底层不重复记录，HTTP 入口记录一次带完整 Throwable 的脱敏日志，并返回稳定的安全错误信封。

## 最小修复

删除传播链中的重复日志，由最外层真实执行边界记录一次完整异常和必要脱敏上下文；用户只接收当前入口拥有的安全失败语义。

## 报告要求

列出完整传播链、重复或缺失的日志事实、最终入口、暴露字段及影响；敏感信息泄露时说明为何提高实际级别。
