# Java 异常专项审计方法

> 仅在 `$nest-audit-java` 选择异常专项模式时读取。本文件定义候选扫描、证据模型和专项输出要求；具体违规判定以规则目录链接的 `NJX-*` 独立细则为准。

## 审计边界

- 只审计异常捕获、传播、日志和入口兜底责任，不扩张为普通 Java 全面审计，也不设计统一异常体系。
- `catch` 是否有价值取决于当前边界是否承担真实且有依据的处理责任，不取决于异常文案是否更详细。
- 日志、读取或拼接 message、修改错误码、转换异常类型、补充相似上下文和重新抛出本身都不构成处理。
- 恢复、补偿、重试、资源或进程清理、线程中断恢复、失败状态收敛和入口协议转换可能构成真实处理，但必须有用户要求、既有契约或当前消费者证据。
- 底层优先保留异常事实，最终入口负责日志和安全呈现；不同入口可以采用不同状态、错误事件、跳转、退出码或用户提示。
- 不把所有 `catch` 机械判错，也不因为包装保留了 cause 就自动认可其处理价值。

## 候选扫描

1. 优先使用 `rg` 定位 `catch`、异常构造、`getMessage()`、错误日志、默认返回值、异步失败完成和入口异常处理；字符串命中只建立候选。
2. 批量或全仓审计先基于最新工作树列出范围内全部 `catch`、异步异常生产者和观察者，并记录候选总数；复核修复时重新扫描，不能沿用上一轮清单。
3. 即使输入是 diff，也要读取命中位置的完整方法、类型、必要调用方和最终入口。

## 五项证据

每个候选至少还原：

1. **来源**：原异常由哪个调用、资源、协议或框架动作产生，原类型、cause、堆栈和中断语义是什么。
2. **动作**：`catch` 内除日志、包装和重抛外，是否真正改变状态、控制流、资源所有权或协议结果。
3. **消费者**：调用方是否按包装后的类型、错误码、字段或状态执行恢复或稳定协议映射。
4. **入口**：异常最终到达 Advice、流式回调、Filter、RPC、Job、线程、CLI 或其他哪个执行边界。
5. **结果**：日志是否完整且只记录一次，用户是否看到内部细节，失败是否被伪装为空数据、未找到或成功。

缺少调用方、入口或契约证据时只能标记未确认，不能仅凭 `catch`、`throw new` 或 `getMessage()` 判定问题。

## 调用链判定

1. 沿调用链核对恢复、补偿、清理、中断恢复、重试、失败状态收敛和入口协议转换是否真实发生，并核对其依据。
2. 同一底层异常存在多个入口时分别核对各入口行为，不为表面统一增加异常壳。
3. 同一异常沿多层重复包装、吞没或记录时按根因合并，列出所有真实成立的 `NJX-*`，不按 `catch` 数量制造问题。
4. 主动创建异常只有在目标项目已规定主动异常类型时才核对该项目规则；不得把主动异常统一约束解释成捕获并转换已有异常的理由。
5. 外部接口、框架回调、生成代码、`InterruptedException` 和致命 `Error` 的既有契约必须单独核实。

## 分类与输出

- 每个候选只能归为“有依据保留”“已证实问题”或“未确认”。
- 第一行给出总体判断，正文只展开已证实问题和影响结论的未确认事实。
- 批量或全仓审计同时给出候选总数和三类数量。
- 每个问题包含规则 ID、级别和标题、准确位置、原异常与 `catch` 动作、传播链和最终入口、用户可见影响、成立证据、反例核对及最小修复方向。
- 没有证实问题时明确范围和结论；最小修复不得顺带重构异常体系。
