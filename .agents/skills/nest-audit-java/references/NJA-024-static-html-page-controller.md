# NJA-024 静态 HTML 被无责任 Page Controller 包装

## 元数据

- 状态：Ready
- 类型：Code Smell
- 质量属性：可维护性、安全性
- 默认级别：普通
- 标签：spring-mvc、controller、static-html、routing、authentication
- 适用范围：Spring MVC 页面 Controller、redirect、forward、额外静态资源映射或静态 HTML 别名已经造成路由冲突、鉴权不等价、错误落页、消费者分裂或可证实维护损害；“直接使用物理 HTML 且只允许根 `/` 例外”仅在目标项目明确启用该规则时检查

## 为什么是问题

页面别名或 redirect 并不天然无责任；canonical URL、SEO、反向代理、稳定产品地址和外部兼容都可能要求非物理地址。通用问题只在多套映射已经造成路由冲突、鉴权不等价、错误落页、消费者分裂或真实维护损害时成立。目标项目明确规定物理 HTML 是唯一入口时，再按其 Page Controller 例外边界检查。

## 触发调查

- `@Controller` 方法只返回 `redirect:` 或 `forward:` 到静态 `.html`，且没有已确认的地址或协议责任；
- 实际静态资源处理器已经交付同一目录，代码又注册额外前缀，可能产生重复消费者或鉴权差异；
- 显式 `ResourceHandler` 已删除，但框架默认映射或依赖自动装配仍能从 `/static/**` 等前缀交付同一资源；
- 同一页面同时存在多个地址，且规范地址、消费者或鉴权责任不明确；
- `*PageController` 没有请求模型、权限决策、协议转换或服务端渲染；
- 页面规范地址、前端链接、登录回跳和鉴权配置指向不同映射。

## 判定所需证据

1. 定位目标物理 HTML、框架默认、依赖自动装配、自定义静态资源处理器和全部生产消费者，并通过当前实际映射或请求证实重复入口；
2. 读取 Controller 完整方法，确认没有服务端渲染、数据装配、权限、签名、租户或外部协议责任；
3. 检查映射是否是当前发布契约、第三方回调、反向代理或其他不能直接迁移的真实入口；
4. 比较保留与删除 Controller 或资源映射后的导航、刷新、canonical URL、代理、鉴权和错误行为，并在当前构建实际请求可能的重复前缀；
5. 核对 HTML 与 CSS/JS/图片、业务 API 的鉴权责任没有被错误捆绑。

只看到 `PageController` 类名、单行 redirect、`addResourceHandler` 或多个 URL 不能单独判定命中。

## 不应报告

- Controller 执行服务端模板渲染、业务数据装配、租户或权限决策、一次性签名或协议转换；
- 部署单元明确要求 `http://IP:端口/` 可进入产品，且 Controller 只映射根 `/`、只重定向到一个规范物理首页、目标继续进入相同 HTML 鉴权链；不得把这个例外外推到 `/index.html` 或业务页面别名；
- 映射是已发布外部契约、第三方回调、SEO/代理规范或框架硬要求，且规范地址、鉴权等价性与退役边界有证据；
- 非 HTML 站点资源、下载或动态内容必须通过 Controller 交付；
- SPA 的服务端 history fallback 是当前明确路由契约，而不是为传统物理 HTML 顺手增加的别名。
- 非根 redirect 或别名承担已确认的 canonical URL、SEO、反向代理、稳定产品地址或外部兼容责任，且与物理资源保持同一鉴权边界。
- 多个地址存在但没有路由冲突、鉴权漂移、消费者分裂或可证实维护损害，且目标项目未启用物理 HTML 唯一入口规则。

## 示例

不合规：`GET /reports` 与 `/reports/index.html` 分别进入不同鉴权链，匿名用户可通过别名绕过限制；或两个资源处理器实际竞争同一路径并产生错误落页。

合规：`GET /reports` 是已发布 canonical URL，由 Controller 保持稳定地址并进入与物理 HTML 相同的鉴权边界。目标项目明确启用物理 HTML 唯一入口规则时，按其例外只保留获准映射。另一类合规场景是 `GET /reports/{id}` 校验当前用户权限，装配服务端模板所需的数据和一次性下载签名。

## 最小修复

消除已证实的路由冲突、鉴权不等价、错误落页或消费者分裂，保留拥有真实地址或协议责任的唯一映射。只有目标项目明确启用物理 HTML 唯一入口规则时，才把生产消费者统一到物理 HTML 并按其根 `/` 等例外处理。不要借此改写业务 API、非页面资源 Controller 或无关页面结构；存在 canonical、代理或兼容契约时保留必要映射并记录规范地址和退役条件。

## 报告要求

报告物理 HTML、Controller 映射、真实消费者和当前映射或请求证据，说明路由冲突、鉴权差异、错误落页、消费者分裂或维护损害，以及已排除的 canonical、代理和外部契约。要求直接使用物理 HTML 或只保留根 `/` 时必须给出目标项目 Rule 来源；缺少具体影响时不因 redirect、forward 或别名形状单独判定命中。
