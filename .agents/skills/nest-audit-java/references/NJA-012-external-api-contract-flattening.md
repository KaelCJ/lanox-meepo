# NJA-012 外部 API 契约被拍平或凭调用方猜测

## 元数据

- 状态：Ready
- 类型：Code Smell
- 质量属性：可靠性、可维护性
- 默认级别：重大
- 标签：external-api、protocol、schema、dto、map、wire-contract
- 适用范围：外部 API、RPC、CLI 协议或 SDK 接入相对当前版本权威契约存在可观察 wire 差异；完整 1:1 类型建模只在目标项目明确启用相应 Java Rule 时检查

## 为什么是问题

`Map`、字段常量或只声明当前消费者所需字段并不天然错误；它们可以忠实表达开放对象或支持向前兼容。问题在于实现没有依据当前实际版本的权威契约，导致 wire 字段名、嵌套层级、必填性、nullable、默认值、枚举、联合分支或错误结构产生真实差异，并影响对端或当前消费者。

反方向的机械翻译也有风险：在尚未确认版本和 schema 时创建完整 SDK、通用 Factory 或层层包装，只是把猜测固化成更多类型。审计目标是“先忠实、后等价简化”，不是追求类或字段数量。

## 触发调查

- 稳定外部结构由 `Map<String, Object>`、`Object`、字符串键或常量拼接，且没有与当前版本 schema 对照；
- Java 类型只包含当前调用方读取的字段，可能漏掉正确解析或发送所必需的分支；
- 外部字段被重命名、拍平、合并或赋默认值，但没有明确的 wire 映射和等价证据；
- 注释声称字段必填、可选或固定，却没有与实际依赖版本匹配的 schema、官方类型或运行证据；
- 外部版本升级后仍沿用旧示例、旧常量或旧 DTO，没有重新核对生成 schema。

## 判定所需证据

1. 定位当前实际使用的外部产品、协议版本、CLI/SDK 版本和启动方式；
2. 取得同版本官方规范、生成 schema、正式客户端类型或等价协议真源，列出当前授权和运行路径实际涉及的方法、请求、响应、通知、错误及字段约束；
3. 对照 Java 序列化结果核对 wire 字段名、嵌套层级、必填、nullable、默认值、枚举和联合分支；
4. 搜索生产构造者、消费者、透传、日志和前端展示，确认缺失或改写结构的可观察影响；
5. 区分稳定结构与协议明确开放的任意 JSON，不能仅凭使用了 `Map` 判断命中；
6. 构造能消除已证实 wire 差异的最小方案；只有目标项目明确启用完整 1:1 建模规则时，才进一步核对其类型与 package 约束，不扩大成未授权的完整 SDK 或未来协议框架。

## 不应报告

- schema 明确允许任意 JSON、附加属性、开放对象或无法静态穷举的联合结构；
- 原始抓包、诊断快照或透明代理有意保留未经解释的 wire 数据，稳定方法边界另有明确类型；
- 当前客户端在协议允许范围内固定选择数值型或字符串型 request id，且不改变对端 contract；
- 代码生成器拥有完整协议模型，人工扩展层只做明确且有证据的等价映射；
- 应用 DTO 有意不暴露全部上游字段，但 infrastructure 协议模型完整，映射边界、信息舍弃和消费者契约均明确；
- 当前授权只实现一个方法，且该方法的完整入参、出参和错误已建模，没有为未使用方法预建 SDK。
- `Map` 或字段子集与当前版本 schema 相容，未知字段可安全忽略，且当前构造者和消费者没有丢失必需语义。

## 示例

不合规：官方 schema 要求嵌套 `clientInfo` 且两个字段必填，实现却把字段拍平并漏发其中一个，服务端因此拒绝请求；问题是实际 wire 差异，不是 `Map` 本身。

不合规：只根据一段文档示例创建响应 DTO，漏掉当前 CLI 生成 schema 中新增的必填字段，却宣称已经 1:1 接入。

合规：依据当前 CLI 生成 schema，当前客户端只建模已授权方法正确互操作所需的 params、result 和 error 分支；未知响应字段按协议允许安全忽略。目标项目另有完整 1:1 建模规则时再按其要求补齐。

合规：协议中的 error data 明确为任意 JSON，因此稳定的 code/message 使用字段，data 保留为 `Object`，没有为未知内容制造假类型。

## 最小修复

取得当前版本协议真源，只为已授权运行路径修复已证实的 wire 字段、层级和分支差异；具体类型化程度与 package 所有权以目标项目已启用的 Java Rule 为准。不要顺带生成全量 SDK、兼容层、Factory 或未来方法占位。

## 报告要求

列出外部协议和版本、协议真源、目标方法、Java 与 wire 的具体差异、当前消费者影响、动态结构与字段子集反例，以及最小兼容修复。要求完整 1:1 类型建模时必须给出目标项目 Rule 来源；无法取得同版本 schema 时明确列为未验证，不把 `Map`、字段数量或猜测写成缺陷事实。
