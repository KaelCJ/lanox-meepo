# NJA-004 重复或绕过基础设施能力

## 元数据

- 状态：Ready
- 类型：Code Smell
- 质量属性：可维护性、可靠性
- 默认级别：重大
- 标签：infrastructure、reuse、nest、dependency、autoconfiguration、json、context、concurrency
- 适用范围：新增或替换通用工具、上下文、JSON、HTTP、trace、日志、并发、标识或生命周期能力，且可能形成多个运行真源；涉及 Nest 具体选型或组件完整装配时，必须有目标项目 Rule 或组件公开契约的明确依据

## 为什么是问题

重复实现只有在多个实现同时拥有同一语义、配置、安全、线程或生命周期时，才形成可证实的双真源风险。某个 artifact 是否完整拥有传递运行栈和自动装配，也必须由其公开契约或目标项目 Rule 证明；仅使用不同库、框架排除项、自定义 Bean 或局部适配器，不足以推出所有权错位。

## 触发调查

- 新增 Util、Helper、Adapter 或包装层实现已有基础设施可能已经提供的同语义能力；
- 直接创建第二套序列化器、HTTP 客户端、线程池或上下文存储，可能与当前运行真源并存；
- Controller、Service、DTO 手工读写 trace、用户、租户或协议元数据；
- 因当前模块未声明依赖，改用 JDK 或第三方库拼装相似能力；该形状只触发核对，不因技术选型不同直接判定。
- 新增或保留 `spring.autoconfigure.exclude`、`@SpringBootApplication(exclude = ...)`、自定义同类 Bean 或启动参数，以关闭、替换或规避已引入 Nest 组件的内部自动配置；
- 声称不再需要某项完整 Nest 能力，却只关闭配置并继续保留提供该能力且没有其他真实消费者的 artifact。

## 判定所需证据

1. 从当前 POM、依赖树和 classpath 确认实际基础设施模块、版本和运行所有者；涉及 Nest 时再读取对应版本源码与公开契约；
2. 按语义搜索现有类型、方法、生产调用方和运行配置，确认候选能力是否真实可用且与新增实现并存；
3. 比较空值、格式、异常、安全、性能、线程、上下文传播、关闭和兼容契约；
4. 核对模块依赖方向与当前任务是否授权新增依赖或进入孵化边界；
5. JSON 场景区分普通序列化、对象转换与树模型、流式 API、格式化、自定义 module 等专属能力；只有目标项目明确指定 `DwJson`、`DwJacksonProcessor` 或其他所有者时才按该选型检查；
6. 并发场景区分接口类型与执行器的实际创建点、线程工厂、上下文传播、拒绝策略和关闭所有权；只有目标项目明确指定 `DwExecutors` 或其他所有者时才按该选型检查，接口声明本身不能证明重复建设；
7. 涉及组件启停或自动配置冲突时，核对 artifact 的自动配置入口、传递依赖、正式配置契约和全部当前消费者，确认能力边界由 artifact、独立开关还是组合根控制；不能只因存在 `enabled` 或框架支持 exclude 就推断采用方拥有拆装权；
8. 指出语义匹配的既有能力及双真源的可观察影响，或用公开契约证明当前自动配置冲突、能力移除本应由特定基础设施所有者承接。

## 不应报告

- 候选能力语义不匹配、版本不可用或依赖方向违法；
- 实现承载明确领域语义，不属于跨领域基础设施；
- 适配器转换真实外部协议且没有复制基础设施主体；
- `ObjectMapper` 由当前版本 `DwJacksonProcessor` 创建，并只承担树模型、文件读写、格式化或局部 Jackson 专属配置；
- 字段或参数使用 `ExecutorService` 接口，而实际执行器由 `DwExecutors` 创建，且上下文传播、拒绝策略与关闭所有权均已核实；
- 独立 CLI 或短生命周期任务使用 Nest 线程工厂并明确 join/关闭，且当前场景没有需要传播的 Web 上下文；
- Nest 组件正式契约明确支持部分启停，保留 artifact 是其他当前消费者所必需，且采用方配置正是组件公开的装配边界；
- 组合根需要与外部实现共存，Nest 组件明确把 Bean 选择、exclude 或覆盖权交给采用方，并已核实不会形成两套运行时真源；
- 只能从名称相似或记忆推测已有能力，未核实源码和 classpath。
- 目标项目没有启用具体基础设施选型，多个实现各自拥有不同语义或生命周期，且不存在运行时双真源或公开装配契约冲突。

## 示例

不合规：同一进程中两套 JSON 或执行器实现同时承担相同协议、上下文传播和关闭责任，调用方分流且输出或生命周期已经不一致；或组件公开契约明确完整拥有数据源装配，采用项目保留组件却用排除项拆掉其中一部分，造成“依赖存在”与“能力不可用”两个事实来源。

合规：目标项目明确指定 `DwJson`、`DwJacksonProcessor` 与 `DwExecutors` 时按其契约复用；未指定时，局部实现拥有独立语义、消费者和关闭边界，不与另一实现竞争同一运行真源。组件公开支持部分启停时，采用方按其契约配置不构成绕过。

## 最小修复

收敛已证实的同语义双真源，保留依赖合法且拥有真实消费者的唯一实现；具体替换目标以目标项目 Rule 和当前组件契约为准，不从本细则强制指定 `DwJson`、`DwJacksonProcessor`、`DwExecutors` 或其他实现。组件不再需要且没有消费者时删除依赖和专属配置；组件仍需保留且公开契约不允许拆装时，由真实所有者修复装配边界。能力确实缺失或当前任务无权修改所有者时停止临时补做，进入获准的基础设施所有权范围。不得为表面复用增加改变外部格式的转换层。

## 报告要求

给出当前依赖版本、目标项目 Rule 或组件公开契约、候选基础设施类型、artifact 与自动配置入口、实际创建点、运行真源和当前消费者；按场景补充 JSON、并发、上下文、关闭或框架配置契约对照，说明双真源或装配冲突的实际影响、不能整体移除的反例和最小所有权修复路径。缺少选型或装配所有权证据时不按具体实现名称判定命中。
