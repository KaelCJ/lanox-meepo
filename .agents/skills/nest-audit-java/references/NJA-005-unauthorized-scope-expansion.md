# NJA-005 未授权范围扩张

## 元数据

- 状态：Ready
- 类型：Code Smell
- 质量属性：可维护性
- 默认级别：重大
- 标签：scope、governance、yagni、compatibility
- 适用范围：包含额外文件、依赖、配置、迁移、兼容层或范围外重构的 Java 改动

## 为什么是问题

未与当前目标建立关系的改动扩大了评审、回归和回退范围，也可能越过模块、数据或外部系统授权。为未来升级预建兼容和扩展尤其容易留下无人维护的永久结构。

## 触发调查

- 改动包含需求未提及的新文件、依赖、配置或模块；
- 顺手重命名、拆包、升级依赖或清理相邻代码；
- 为没有当前消费者的旧格式、旧接口或未来版本增加兼容层；
- 用“顺便”“以后需要”“更标准”解释改动，而没有当前事实依据。

## 判定所需证据

1. 读取用户目标、已确认方案、目标步骤和项目授权边界；
2. 将每个新增或显著修改对象映射到需求、规则或已验证问题；
3. 分析额外改动的消费者、回归范围、副作用和回退成本；
4. 证明额外对象不是完成目标的必要最小部分。

## 不应报告

- 改动是完成目标所必需的调用方同步、错误处理或验证资产；
- 项目规则明确要求同一变更闭环更新消费者；
- 用户已明确授权准确范围的迁移、清理或重构；
- 额外文件仅是构建工具产生且没有进入提交范围的可恢复产物。

## 示例

不合规：修复一个空值问题时同时新增策略接口、配置开关和旧行为兼容层，当前没有第二实现或旧消费者。

合规：只修改问题链路及必须同步的真实消费者；其他潜在重构记录为建议，不进入本次代码。

## 最小修复

撤回目标外改动，保留完成当前需求和必要验证的最小集合。确需扩大范围时先说明原因、影响、不做项和回退边界，取得明确授权后再实施。

## 报告要求

逐项列出无法映射的改动、当前目标边界、具体扩大影响、是否可独立回退以及最小收缩建议。
