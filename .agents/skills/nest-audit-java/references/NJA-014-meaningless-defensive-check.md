# NJA-014 无真实语义的防御检查

## 元数据

- 状态：Ready
- 类型：Code Smell
- 质量属性：可维护性、可靠性
- 默认级别：普通
- 标签：defensive-check、null-check、precondition、race、fail-fast
- 适用范围：Java 方法中的参数空值、不可能状态、瞬时存活状态和其他预防性检查；不把所有校验或 `if` 机械视为问题

## 为什么是问题

只把调用方编程错误提前若干行抛出、换成自定义异常或改善错误文案的检查，没有保护业务、协议、资源或生命周期，却增加分支、错误文本和伪契约。对进程、连接等瞬时状态先检查再操作还会制造错误的安全感：检查成立后状态仍可立刻变化，真正的 I/O 失败路径依然必须存在。这类代码扩大维护面，却不能提供它表面承诺的保证。

## 触发调查

- typed 内部方法在首次解引用前手写 `argument == null`、`Objects.requireNonNull` 或同义断言；
- 参数只由仓内构造器或固定调用方创建，检查失败后仅抛出 `IllegalArgumentException`、`IllegalStateException` 或自定义包装异常；
- `isAlive`、`isConnected`、`exists`、缓存命中或状态枚举预检后立即执行仍可能独立失败的 I/O 或并发操作；
- 检查的唯一说明是“防御性编程”“更友好报错”“public 方法可能被误用”或“提前失败”。

## 判定所需证据

1. 定位全部生产调用方、反射/SPI/框架入口和参数来源，确认输入是否由受信 typed 代码直接构造；
2. 比较保留与删除检查后的异常类型、失败位置、日志、资源清理、协议输出和调用方恢复行为；
3. 查明检查是否承载业务规则、外部协议必填性、安全边界、资源容量、索引范围、事务、并发、线程中断、进程关闭或幂等生命周期不变量；
4. 对瞬时状态检查核对检查与后续动作是否原子，以及后续真实操作是否已经报告同一失败；
5. 构造最小删除方案，确认不会把受控失败变成静默成功、无效 wire 数据、资源泄漏或不可诊断的远端错误。

## 不应报告

- 用户、HTTP、文件、消息、数据库或外部系统提供的不受信输入需要在边界校验；
- 校验维护协议必填字段、联合类型互斥关系、索引/范围、安全策略、资源上限或持久化不变量；
- 检查失败触发必要的资源回收、事务回滚、重试/回退、错误协议转换，或调用方按稳定异常类型恢复；
- `AtomicBoolean.compareAndSet`、锁、事务条件或单次状态转换本身提供原子生命周期保证，而非先检查再操作；
- 只能看到一个空值检查或状态判断，尚未核实调用方、输入信任边界和删除后的可观察行为。

## 示例

不合规：内部 typed request 只由若干 `new XxxRequest(...)` 调用方传入，方法先判断 request 是否为 `null` 并抛出自定义状态异常，随后立即调用 `request.method()`；没有调用方依赖该异常，也没有恢复或清理差异。

不合规：收到初始化响应后先调用 `process.isAlive()`，通过后再写初始化完成通知；进程可在检查后退出，后续写入本身已经能够报告断连，因此预检不提供存活保证。

合规：解析外部 JSON-RPC 成功响应时拒绝协议要求必填但缺失的 `result`，避免把无效 wire 消息当成成功结果进入业务层。

合规：`close()` 使用原子状态转换保证资源只回收一次；该判断拥有并发语义，不是重复的调用方参数防御。

## 最小修复

删除无语义检查及其专属错误文本，让后续真实解引用、I/O 或协议动作成为唯一失败路径。若调查发现需要稳定异常契约、原子状态保证、资源清理或边界校验，则保留最局部的真实机制并明确其所有者；不得为删除一个检查新建 Validator、Helper、异常层次或通用防御框架。

## 报告要求

报告准确位置、全部真实调用方和输入来源、检查当前改变的异常或行为、后续自然失败点、已排除的协议/安全/资源/并发反例，以及最小删除后的行为边界。若无法证明输入受信或删除后行为等价，标为未验证，不判定命中。
