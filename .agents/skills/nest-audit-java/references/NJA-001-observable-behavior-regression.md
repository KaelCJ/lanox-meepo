# NJA-001 行为变化缺少等价证据

## 元数据

- 状态：Ready
- 类型：Bug
- 质量属性：可靠性
- 默认级别：重大
- 标签：refactoring、compatibility、behavior
- 适用范围：删除、精简、内联、拆分、改签名、替换实现或迁移 Java 代码

## 为什么是问题

重构如果改变真实入口的返回值、副作用、异常、状态、时序或兼容契约，就不是等价重构。代码更少、编译成功或局部调用正常不能证明消费者行为保持，最坏结果可能是生产路径静默丢功能、破坏历史数据或改变安全边界。

## 触发调查

- 删除原有分支、类型、字段、回调、异常转换或持久化动作；
- 把多步流程压缩到唯一调用方，或以新库、新框架能力替换旧实现；
- 修改公共方法、DTO、序列化、注解、SPI、反射或框架回调可见结构；
- 以“没有调用方”删除代码，但只搜索了直接 Java 引用。

## 判定所需证据

1. 定位改动前后真实用户入口和全部生产消费者；
2. 对照正常、失败和边界路径的输出、副作用、异常、状态与时序；
3. 搜索反射、SPI、注解注册、配置、生成代码和外部契约消费者；
4. 证明现有验证实际经过受影响入口，并覆盖受影响的历史状态；
5. 指出至少一项已改变或尚无法证明等价的可观察行为。

## 不应报告

- 改动只删除确证不可达且没有反射、配置或外部契约消费者的代码；
- 用户明确授权改变对应行为，且连带影响仍在授权范围内；
- 生成产物变化来自当前获准的生成真源，并已验证消费者兼容；
- 只有格式、注释或等价局部表达变化，没有行为或契约影响。

## 示例

不合规：删除一个看似无调用方的状态恢复分支，只凭 `rg` 未命中方法名和编译成功认定等价，没有检查框架注册及历史 Session。

合规：确认入口、注册方式、历史状态和失败路径均无消费者后删除分支，并保留能证明当前范围的验证记录；不能确认的部分明确停止删除。

## 最小修复

恢复受影响行为，或补齐调用方和契约证据后采用最小等价实现。用户确需改变行为时，把行为变化及连带影响纳入明确需求和验证，不把它包装为纯重构。

## 报告要求

列出真实入口、受影响消费者、具体行为差异、已搜索的隐式消费者、当前证据能证明与不能证明的范围。
