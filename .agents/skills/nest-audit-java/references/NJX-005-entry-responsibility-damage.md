# NJX-005 入口责任被底层包装破坏

## 元数据

- 状态：Ready
- 类型：Bug
- 质量属性：可靠性、可维护性
- 默认级别：重大
- 标签：exception、boundary、advice、stream、retry、user-message
- 适用范围：被多个入口消费的底层异常包装、错误 DTO 和用户提示拼装

## 为什么是问题

底层强制统一异常类型或用户提示会抹平不同入口需要的失败语义，使 Advice、断流、中断、鉴权、重试或任务状态分支无法识别真实故障。入口因此可能返回错误状态、错误事件或错误提示。

## 触发调查

- 底层转换后，Advice、流式回调、重试器或任务入口不再识别原异常；
- 底层拼装用户提示、状态码、错误 DTO 或跨入口通用 message；
- 为 HTTP、流式、HTML、RPC、任务或 CLI 强制使用同一种异常壳。

## 判定所需证据

1. 定位底层原异常、包装动作及全部真实入口；
2. 对每个入口对照保留包装和直接传播时的状态、事件、跳转、日志、取消或提示行为；
3. 核对当前底层是否拥有任何入口协议；
4. 证明删除底层包装后现有入口能够正确兜底，而包装正在破坏至少一个入口责任。

## 不应报告

- 当前代码本身就是真实入口，并按该入口既有协议完成安全映射、资源收口或用户流程转换；
- 底层类型是所有当前消费者稳定依赖的正式领域契约，而非为了表面统一临时增加的异常壳；
- 删除包装后入口无法履行既有协议，且没有上层可以等价承接转换。

## 示例

不合规：共享 Service 把鉴权异常、上游断流和任务取消都转换为通用业务异常，导致 HTTP Advice 返回 500、流式入口发送错误事件、任务入口继续重试。

合规：Service 保留原异常，各入口分别映射为 HTTP 状态、流式结束事件或任务取消状态，并在各自边界安全呈现。

## 最小修复

恢复原异常传播，让各真实入口分别负责日志、安全呈现和协议转换；只保留有稳定消费者证据的领域异常，不建立新的跨入口统一异常体系。

## 报告要求

列出原异常、底层包装、受影响入口及各入口行为差异，说明当前层为何没有协议责任、适用反例和最小责任回归方案。
