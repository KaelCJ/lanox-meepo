# NJA-020 无真实包级契约的 `package-info.java`

## 元数据

- 状态：Ready
- 类型：Code Smell
- 质量属性：可维护性
- 默认级别：普通
- 标签：package-info、javadoc、package-annotation、placeholder、documentation
- 适用范围：人工维护 Java 源码中新增、修改或批量保留的 `package-info.java`；不授权修改生成代码、外部只读源码或上游制品

## 为什么是问题

`package-info.java` 是包级注解和包级文档的容器，不是 package 存在的必要声明。只复述目录名、类型类别或未来设想的文件会增加源码数量、审阅噪声和失真维护点，却不向编译器、工具或使用者提供新增契约。批量要求“每包必有”还会诱导 Agent 为满足形态制造空包和低信息 Javadoc，使真正重要的包注解、协议边界和生命周期说明更难识别。

## 触发调查

- 新增或修改的 `package-info.java` 只包含 Javadoc 和 `package` 声明，没有包注解；
- Javadoc 只把包名翻译成“某 DTO”“某 Service”“某基础设施”，或罗列包内类型；
- 文案使用“未来”“后续”“预留”“逐项加入”等没有当前消费者的占位语义；
- 一个重构、迁移或生成动作按目录批量产生 `package-info.java`；
- 项目用文件数量、目录完整或可选 Javadoc 检查证明文件必要。

这些形状只触发调查；文件短、无注解或每个类型已有 Javadoc不能单独判定命中。

## 判定所需证据

1. 完整读取文件，核对包声明上的注解、import、Javadoc 链接和自定义标签；
2. 搜索构建、Javadoc、Checkstyle、生成器、框架、反射和发布配置是否实际消费该包信息；
3. 读取同包代表类型与相邻包，确认文档是否只重复类型 Javadoc、package 路径或模块入口已有事实；
4. 定位文档宣称的协议版本、wire/adapter 分界、资源生命周期、生成所有权或包间职责是否有当前消费者，以及删除后是否失去唯一契约真源；
5. 区分人工源码、生成产物、外部只读源码和当前授权范围；无法核实所有权或消费时列为未验证，不判定删除。

## 不应报告

- 包声明带有编译期、运行时或工具实际消费的注解，例如明确采用的 nullability、参数默认约束或框架注册；
- 文档是多个类型共同依赖的唯一包级契约，说明无法从单个类型推出的协议版本、包内外使用约束、wire 与 adapter 边界、资源生命周期或生成所有权；
- 发布 API 的当前外部契约明确要求包级 Javadoc，并能定位实际文档消费者；
- 生成器拥有的 `package-info.java`、正式外部只读源码或当前授权范围外的制品；
- 删除会让仍被引用的包级链接、文档输出或工具行为失效，且没有已验证替代所有者。

## 不合规与合规示例

不合规：

```java
/** 用户响应 DTO。 */
package example.application.dto.rsp.user;
```

包名和类型本身已表达相同信息，文件没有新增契约或工具行为。

合规：

```java
/**
 * 直接映射协议 v2 wire schema 的类型；本包类型不得承载客户端重试和超时策略。
 */
@ParametersAreNonnullByDefault
package example.client.protocol.v2;

import javax.annotation.ParametersAreNonnullByDefault;
```

注解由工具消费，文档同时约束多个协议类型并明确 wire 与客户端策略边界。

## 最小修复

没有真实包级用途时删除 `package-info.java`，不创建替代占位文件、不删除 package 目录或移动其他类型。信息有价值但所有者错误时，写回最准确的类型、模块、协议真源或项目文档后再删除重复文件。存在包注解或唯一包级契约时保留并只修正已经证实失真的内容；不要为统一风格批量改写。

## 报告要求

报告准确文件、当前内容、包注解/工具消费核对结果、重复或占位证据、真实消费者与所有权边界，以及删除或迁移后的最小影响。批量命中可以按同一根因合并报告，但仍需给出完整文件清单或可复核范围。静态内容检查只能证明源码形状，不能单独证明生成、发布文档或框架行为不受影响。
