# NJX-003 吞异常并制造假结果

## 元数据

- 状态：Ready
- 类型：Bug
- 质量属性：可靠性
- 默认级别：重大
- 标签：exception、swallow、fallback、default-value、false-success
- 适用范围：捕获异常后返回默认结果、继续执行或结束失败传播的代码

## 为什么是问题

技术失败被转换为空数据、未找到、默认值或成功后，调用方无法区分真实业务结果和执行失败，可能继续提交错误状态、覆盖数据或向用户报告成功。

## 触发调查

- `catch` 后返回 `null`、空集合、`false`、默认对象或成功响应；
- 只记录日志后继续处理，或异步链未完成为失败；
- 捕获异常后把当前项、当前步骤或整个任务静默跳过。

## 判定所需证据

1. 定位原异常和 `catch` 产生的替代结果；
2. 追踪调用方如何解释该结果以及最终用户可见行为和副作用；
3. 核对契约是否明确允许 best-effort、坏数据隔离、缓存降级或默认值；
4. 核对降级时是否保留必要状态、观测和部分失败语义。

## 不应报告

- 契约明确允许隔离单条坏数据、采用缓存或默认值，并且状态和观测与该语义一致；
- 观察流已经断开，当前入口按既有协议结束无消费者的输出且完成资源收口；
- 默认结果与技术失败在当前契约中确实等价，且消费者不会据此执行错误副作用。

## 示例

不合规：数据库读取失败后返回空集合，Controller 将其呈现为“没有数据”，调用方无法知道查询未执行成功。

合规：批量导入契约明确允许跳过单条坏记录，结果中记录失败项和原因，最终状态也反映部分成功。

## 最小修复

让异常到达真实兜底边界；产品确需降级时先依据既有或获准契约保留明确的失败状态、观测和消费者可区分结果。

## 报告要求

给出原失败、伪造结果、调用方解释、最终副作用或用户结果、降级契约核对和最小传播或状态修复。
