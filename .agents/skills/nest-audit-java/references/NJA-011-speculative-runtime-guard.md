# NJA-011 无当前依据的运行限制或保护分支

## 元数据

- 状态：Ready
- 类型：Code Smell
- 质量属性：可靠性、可维护性
- 默认级别：普通
- 标签：runtime、quota、limit、retry、fallback、compatibility
- 适用范围：新增或保留 quota、Session/连接上限、限流、重试、fallback、兼容分支、缓存、保护开关和预防性拒绝的 Java 实现

## 为什么是问题

没有当前依据的保护逻辑会主动拒绝本可完成的请求、生成额外状态与错误码，并把未来假设变成当前维护成本。阈值、恢复和消费者没有事实来源时，这类代码无法证明提高可靠性，反而可能掩盖真实故障或让本地 POC 无故受限。

## 触发调查

- 按用户、Owner、Session、连接、请求或时间窗口计数并拒绝；
- 新增最大数量、速率、重试次数、fallback、兼容模式、缓存或保护开关；
- 为尚不存在的消费者保留旧路径、旧状态、旧错误码或双写分支；
- 注释只说明“防止未来过载”“为生产准备”或“更安全”，没有当前证据。

## 判定所需证据

1. 定位该分支改变的入口、状态、响应、副作用和真实消费者；
2. 查明受保护的资源或外部契约，以及阈值、触发条件和恢复方式的来源；
3. 核对当前需求、安全策略、协议文档、资源测量、故障记录或可复核运行证据；
4. 检查并发、内存、文件、模型或外部 API 成本、不受信输入和幂等语义是否构成硬边界；
5. 构造删除该分支后的最小行为并验证不会破坏真实安全、资源和兼容契约。

## 不应报告

- 不受信输入长度、协议硬上限、内存或文件容量、模型与外部 API 成本有明确边界；
- 并发互斥、进程或线程生命周期、事务一致性和幂等重试有当前可复核依据；
- 外部服务明确返回配额或速率限制，当前实现按协议处理并保留可观测恢复；
- 兼容分支仍有真实生产消费者或迁移窗口，且退出条件和所有者明确；
- 只能从常量名、`if`、计数器或 `max` 字样推测存在过度保护，未核实行为和依据。

## 示例

不合规：单用户本地连接 POC 按 Owner 限制最多若干 Session，仅以未来可能多用户部署为理由，达到阈值后返回新的失败状态。

合规：上传入口依据已确认的文件容量和内存预算拒绝超限输入；阈值来源、错误语义和恢复方式均可定位，且没有引入通用配额框架。

## 最小修复

删除没有当前依据的限制、错误码、配置和兼容分支，恢复最小可执行路径。确有硬边界时保留最局部的检查并补足来源、触发行为和恢复语义；不得为修复单点问题新建 quota、策略或保护框架。

## 报告要求

给出入口与准确位置、受保护资源、阈值或分支来源、当前消费者、触发后的可观察行为、已检查的安全与资源反例，以及删除或收窄后的行为边界和未验证项。
