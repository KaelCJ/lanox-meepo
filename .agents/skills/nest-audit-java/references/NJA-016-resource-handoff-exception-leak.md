# NJA-016 资源所有权交接前的异常路径泄漏

## 元数据

- 状态：Ready
- 类型：Bug
- 质量属性：可靠性
- 默认级别：重大
- 标签：resource、lifecycle、Throwable、cleanup、ownership、suppressed
- 适用范围：Java 中进程、线程、执行器、连接、流、文件/设备句柄、锁、临时目录和其他显式生命周期资源的创建、部分初始化与所有权交接；不要求普通业务 catch 机械改成 `Throwable`

## 为什么是问题

资源已经创建但尚未成功返回、登记或转交时，创建方法仍负有关闭责任。如果该窗口只捕获 `RuntimeException` 或少数预期异常，构造、listener 启动、握手、通知、登记以及 `Error` 等其他失败会绕过清理，留下子进程、线程、句柄或连接。若清理异常直接覆盖原异常，还会丢失真正失败原因，使泄漏与故障难以诊断。

## 触发调查

- `ProcessBuilder.start()`、Client/Session/Runtime 构造、流/句柄打开后，成功 `return` 或容器登记前存在可抛异常操作；
- 失败分支只 `catch (RuntimeException)`、`catch (Exception)` 或只处理 I/O/中断，但资源可能在其他 `Throwable` 后仍存活；
- owner 构造发生在保护区外，构造失败后底层资源无人关闭；
- catch 中直接 `close()`/`destroy()` 后 `throw original`，但清理抛错会覆盖 original；
- 资源先放入 Map/Registry，再启动 listener、线程或后续初始化，失败后只清理局部状态或只移除登记。

## 判定所需证据

1. 定位资源实际创建点、当前 owner、成功交接点和所有关闭入口；
2. 枚举创建到交接之间的构造、包装、线程/reader/listener 启动、握手、通知、状态更新和登记操作，并确认它们可能抛出的异常类别；
3. 沿每条异常路径核对资源是否仍存活、是否从容器移除、是否有其他 owner 保证回收；
4. 核对失败清理是否覆盖全部当前自有资源、是否保持原异常为主异常并把清理错误设为 suppressed；
5. 核对 `InterruptedException`、`Error`、幂等关闭、并发交接和成功后生命周期，防止修复引入双重关闭或吞错。

## 不应报告

- try-with-resources 或等价结构已覆盖完整作用域，资源不会在成功返回后继续存活；
- 资源创建与原子登记由框架/生命周期容器完成，失败时容器有当前可验证的回滚与关闭保证；
- 创建后立即成功交接，保护窗口内没有其他可能失败的操作；
- 异常边界是异步任务隔离或普通业务转换，当前方法并不拥有需要回收的资源；
- 只能看到 `catch (Exception)` 字符串，尚未确认资源、owner、交接点和遗漏路径。

## 不合规与合规示例

不合规：启动子进程并构造 Client，完成 reader 启动和握手后返回；只捕获 `RuntimeException` 并调用 `client.close()`。Client 构造失败时进程无人关闭，`Error` 也绕过 catch，且 `close()` 的失败可能覆盖握手原异常。

合规：从进程启动后进入所有权保护区；Client 尚未构造时直接终止进程，已构造时调用幂等 close；捕获窄生命周期边界的 `Throwable`，清理失败追加到 original 的 suppressed，随后保留 `RuntimeException`/`Error` 原类型传播，成功返回后由调用方接管。

合规例外：局部输入流使用 try-with-resources 读取完即关闭，方法不返回该流，也不存在跨作用域所有权交接。

## 最小修复

把资源创建后的全部部分初始化步骤纳入同一个所有权保护区；在 owner 构造前后分别保留可执行的底层/高层清理入口；用窄 `catch (Throwable)` 仅承担失败清理，把清理异常加入原异常的 suppressed 后按原异常语义传播。若资源先登记再启动，失败时同时移除登记并关闭资源；不新增通用生命周期框架或改写无关业务 catch。

## 报告要求

报告资源、创建点、当前 owner、成功交接点、漏清理的准确异常路径、可能遗留的资源/状态、原异常是否会被覆盖、默认与实际级别以及最小修复。必须列出至少一个不命中的所有权反例；证据不足时标为未验证，不按 catch 类型单独判定。
