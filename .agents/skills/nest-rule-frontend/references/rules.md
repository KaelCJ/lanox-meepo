# Frontend Rule

> 本文件是 `$nest-rule-frontend` 当前唯一生效的前端产出与审计规则正文；按 Skill 按需读取专题，其他迁移对照不生效。

## 目录

- [通用](#通用)：适用于所有前端设计、产出和审计，包含 `FE-001`～`FE-003`。
- [排版](#排版)：命中字体或文字布局事实时读取，包含 `FE-004`～`FE-009`。
- [公共能力](#公共能力)：命中跨页面/跨应用复用机制时读取，包含 `FE-010`～`FE-013`。
- [页面入口](#页面入口)：命中物理 HTML 地址、映射或鉴权时读取，包含 `FE-014`。

## 通用

### 适用与例外

- 适用于 HTML、CSS、JavaScript、TypeScript、前端组件、前端主题、页面 Shell（UI Shell）、页面入口（含微前端入口）和前端资源的设计、创建、修改、生成、重构与审计。
- 只有用户明确决定或当前项目硬契约才能建立例外；个人建议、文件行数和未来设想不算授权。规则与用户决定冲突时，先说明冲突、影响和范围，得到决定后再写入。

### FE-001 前端实现保持功能完整与最小充分

- 先满足功能完整性、用户可见行为、安全边界和已确认性能，再保留当前需求真正需要的代码和结构。
- 先打通最小可运行纵向链路；不提前加入预防性抽象、无消费者配置、空包装、纯转发、Registry 或未来扩展点，也不为尚未实现的复杂度改造现有链路。本条是实施边界，不等于端到端测试结论。

### FE-002 前端应用保持所有权与关注点分离

- 每个应用或独立入口拥有自己的私有 HTML、脚本、样式、状态和资源，不得引用兄弟应用私有资源或内部全局状态；公共资源的位置和交付边界服从项目入口。
- 页面消费共享 Shell/主题时只放自己的身份、业务操作和内容，不重复全局导航，也不另建与共享主题竞争的整套背景、表面、文字、边框和强调色。
- 每个文件和模块保持明确职责；API、状态、领域编排、DOM、事件和样式有独立变化原因时按真实所有者分开，不持续堆在单个入口、脚本或全局对象里；按职责拆，不按行数机械拆，不用空包装、重复导出、转发层或无消费者注册机制制造模块化。
- 只有语义稳定且有至少两个真实跨应用消费者时才上收公共层；单一消费者和领域专属能力留在所属应用。

### FE-003 每次前端变更必须完成视觉审计

- 创建、修改或重构 HTML、CSS、JavaScript、TypeScript、前端组件、前端主题、页面 Shell（UI Shell）或其他用户可见资源后，必须用本轮构建，从产品支持的真实页面入口在真实浏览器审计。功能调用成功、DOM `visible`、元素可点击、控制台无错、静态扫描或无横向溢出都不能替代视觉审计。
- 至少覆盖直接变更页面及其真实消费者；页面较少时逐页全量，不以抽样代替。共享主题、Shell、布局、token 或共享组件变化覆盖全部当前可达页面和支持主题；页面私有变化覆盖默认主题、受影响主题和受影响断点。
- 逐页查看实际截图，并读取计算后样式，核对关键文字和控件颜色；检查文字和控件可读性、前景/背景对比度、禁用/可用辨识、裁剪、溢出、遮挡、错位、空白、焦点和响应式布局。非禁用普通文字对比度至少 `4.5:1`，大号文字至少 `3:1`；禁用控件仍须可读且不能与可用状态混淆。
- 必须审计本轮源码已进入的实际交付资源；页面仍提供旧构建时，记录为未通过前提，不得用旧截图证明通过。
- 覆盖真实可达的默认、空数据、禁用、加载、错误、成功和本次变更影响的交互后状态；不得为凑状态伪造接口、数据或行为。因权限、真实数据、外部依赖或安全边界不可进入的状态，明确记为未审计，不得写成视觉通过。
- 交付时分开报告功能测试、结构/溢出检查和视觉审计，并记录页面、主题、状态和断点。没有成功截图、逐页观察或关键控件检查时，只报告已做检查，不能宣称 UI、主题矩阵或视觉审计通过。

### FE-003A 自然语言表单输入规范化（仅适用 Meepo 前端）

> 本节仅适用于 Meepo 产品前端的自然语言表单；不约束代码外记录、非自然语言字段。

- 对用户提交的自然语言字段，前端在提交前去除首尾空白，并在结果为空时阻止提交、保留表单可修正状态并给出当前界面已有的简洁提示。
- 只对明确属于自然语言输入的字段执行本规则；密码、代码、路径、表达式、签名、文件内容、协议载荷和其他需要保留精确字符的字段不得机械套用。
- 提交给后端的自然语言使用前端规范后的值；前端不得借此改写用户语义、合并段落、替换内部空白或猜测业务字段。
- 新建或修改自然语言表单时，先确认字段所有权、空值语义、提交 DTO 和后端接口契约，再实现 trim、空值拦截和提示。
- 既有表单的其他字段、错误文案和交互不因本规则被批量迁移；当前目标之外的问题只报告位置和影响。

### 通用产出边界

- 设计或写代码前先应用本节及命中的专题；不要等写完再靠扫描或构建失败纠正设计。
- 启用规则不授权批量拆分、清理或迁移既有前端；范围外问题只报告位置和影响。

## 排版

### 适用边界与方法

- 本节适用于字体、字号、行高、字重、字距、数字、代码文本、截断和字体资源。后台、工作台、编辑器、对话、配置和数据管理默认使用产品界面尺度；营销、品牌 Hero、长篇阅读和可视化可另建命名独立的展示尺度。
- 先确定文本角色和阅读优先级，再选字号/行高、字体族、字重和数字特性，最后在真实语言、数据、容器和平台验证。已有品牌、平台、无障碍或设计系统契约更强时按契约执行，并记录偏离；字体族负责可读性和气质，不代替信息架构。
- 产品型操作界面（导航、侧栏、工具栏、菜单、按钮、表单、表格、列表、对话框、状态、提示和正文）默认使用公共字体体系，并从公共字体族、文本角色、字号/行高配对和字重规则中选择；页面不另维护基础字体栈或任意字号阶梯。用户说“自由设计”只允许建立有名称、有语义角色/token 的局部展示语言，不表示可以任意写字号、字重或字距；其中的操作界面仍用公共体系，除非用户另行明确完整字体例外。局部展示体系可以覆盖公共尺度，但不得改写公共 token、影响其他消费者或扩散为普通控件字号。
- 只有公共尺度无法表达稳定的真实语义时才建立字体例外，并记录所有者、原因、范围和退出条件。层级优先靠语义位置、留白、颜色和有限字重表达；不要用越来越多的字号、极端字重、大字距或全大写代替信息架构。

### FE-004 先定义文本角色，再使用统一字号尺度

产品界面默认使用以下字号/行高配对；实现可用不同 token 名，但语义和配对必须稳定，不能只复用字号而随意改行高：

| 语义角色 | 字号 / 行高 | 默认用途 |
|---|---:|---|
| `micro` | `11px / 15px` | 时间戳、计数器、徽标和低频短标签；不得承载操作说明、正文或关键信息 |
| `caption` | `12px / 16px` | 次要信息、辅助说明和列表元数据 |
| `label` | `13px / 18px` | 紧凑控件标签、表头和高密度元数据行 |
| `body` | `14px / 20px` | 产品正文、菜单、列表主信息和常规控件文字 |
| `body-lg` | `15px / 22px` | 对话正文、引导说明和舒展阅读内容 |
| `title-sm` | `16px / 24px` | 面板、小节和紧凑页面标题 |
| `title` | `18px / 28px` | 主要分区标题 |
| `title-lg` | `20px / 28px` | 卡片组、对话框或页面重要标题 |
| `display-sm` | `24px / 32px` | 页面主标题、空状态标题；不得用于普通侧栏和工具栏 |
| `display` | `36px / 40px` | 少量产品级关键数字或展示标题；不得进入高频工作区 |

- 同一角色跨页面保持同一尺度；紧凑度用容器高度、内边距和信息取舍调整，不把正文缩到 `9px` 或 `10px`。
- 普通界面不得新增半像素或只差 `1px` 的局部字号。只有现有角色无法表达稳定、跨组件语义时，才在公共尺度中增加角色。
- 响应式优先改变结构、宽度、换行和信息显隐；正文和控件文字不得随视口连续缩放，`clamp()` 只用于明确的展示排版。

### FE-005 字体族按内容和平台选择

- 至少定义 `UI Sans` 和 `Mono` 两个语义字体族；只有确有长篇阅读、编辑出版或品牌需求时才增加 `Editorial/Serif`。组件消费 token，不各自维护字体列表。
- 先在目标 Windows、macOS 或 Web 环境核对简体中文常用字、标点、数字和中英文混排的实际命中；可用拉丁 UI 字体加系统中文回退，但不能假设拉丁品牌字体覆盖中文。
- 字体栈须有系统回退，Web Font 失败时页面仍可用。引入 Web Font 前核对授权、制品来源、字符子集、体积、缓存、加载时序和布局偏移；不得只为像参考产品而引入外部依赖。
- 默认不伪造字体能力；未提供的粗细或斜体不得依赖浏览器合成制造关键样式。表单控件、按钮、输入框和弹窗继承所属界面的语义字体族。

参考结构（具体名称由项目决定）：

```css
:root {
    --font-ui: "<Latin UI Font>", ui-sans-serif, system-ui, -apple-system,
        "Segoe UI", "PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif;
    --font-mono: "<Mono Font>", "Cascadia Mono", "SFMono-Regular", Consolas, monospace;
}
```

### FE-006 字重、字距和大小写保持克制

- 默认使用 `400` 正文、`500` 标签/中等强调、`600` 标题/强强调；`700` 只用于少量确需更强识别的位置，不散布 `650`、`680`、`750` 等无语义字重。
- 一个层级优先一个主要强调信号；字号、粗体、强调色、全大写和大字距不能无理由叠加，也不要用多种信号同时表达同一选中状态。中文正文、标签和标题默认 `letter-spacing: 0`，不能用字距补救过小字号。
- 全大写只用于短小稳定的拉丁缩写或 overline，不转换用户内容、路径、模型名和领域名。负字距只用于真实验证过的大号展示标题，任何字距例外都检查混排、标点和回退字体。

### FE-007 正文、数字、代码和图标各归其语义

- 等宽字体只用于代码、命令、路径、日志、标识符和确需逐字符对齐的内容；时间、状态、普通元数据或“技术感”不是理由。
- 表格数值、金额、计数器和时间序列需要纵向比较时优先 `font-variant-numeric: tabular-nums`；不需对齐的数字保持正文排版，不得用空格或手工补零模拟对齐。
- 不用 `+`、`×`、`⌕`、`⌁` 等文本字符冒充图标；使用同一视觉系统的 SVG/图标组件，并为图标操作提供可访问名称。
- 可从上下文恢复的列表预览可以截断；名称、错误、权限提示和下一步操作等关键信息必须可展开、换行或等价完整读取。

### FE-008 字体令牌必须成为实现约束

- 公共主题为每个文本角色同时声明字号和行高 token，组件按角色消费，不得在私有样式复制无语义字号阶梯。
- 新界面从公共角色选择；改旧界面只迁移本轮变更和真实受影响消费者，不因本规则擅自全站换字体或批量调布局。
- 扫描发现越界字号、任意字重、私有字体栈或文本字符图标时，逐项归入迁移到公共角色、已有记录的例外或本轮范围外既有问题；不能只因“看起来还行”忽略新增偏离。
- 设计、实现和验收用同一角色名；讨论“太小”要落到角色，不能只给新像素值。

### FE-009 字体变更必须真实验收

- 字体、字号、行高、字重、字距或字体资源变化时，在 `FE-003` 基础上用真实浏览器读取关键文本的计算后字体族、字号、行高和字重；声明 CSS 不代表实际命中。
- 至少覆盖中文、英文、数字、标点、中英文混排、长标题、长辅助信息、空值、错误和真实代码/路径，以及默认、选中、悬停、聚焦、禁用和截断状态。
- 在支持的平台、主题、关键断点和浏览器缩放下检查裁切、重叠、异常换行、层级失衡和布局跳动；公共 token 或字体资源变化覆盖全部真实消费者。
- 交付记录变化的文本角色、实际命中的字体、审计范围和未覆盖项。参考截图、静态 CSS 对比和单一空状态不能替代真实数据验收。

### 排版产出边界

- 交付字体相关内容时说明文本角色映射；公共组件或主题变化同时说明消费者和迁移边界。
- 偏离默认尺度时记录所有者、产品语义、证据、影响范围、退出条件和验收结果；“参考产品如此”“更有设计感”或个人偏好不单独构成例外。

## 公共能力

### 适用边界

- 用户明确提出公共、复用、统一、组件化或功能套件，准备创建/修改公共源码，或发现两个以上界面共享同类交互/协议机制时读取本节。
- 只复用颜色、字号等 token，或只有相似外观而没有独立行为契约时，按排版/通用规则处理，不单独建立公共能力。用户决定、项目入口和产品规则优先；冲突且会改变流程、消费者或安全边界时先取得决定。

### FE-010 公共化先识别稳定原语和完整消费者

- 写入前从用户原始页面、操作和目标提炼最小稳定原语，不以文件、目录、组件名、第一个页面、`common/shared` 位置、两处引用或包装层证明公共化。
- 横向检索项目声明的全部页面、应用、Agent 和 POC，清点相同底层机制或同类用户目标。每个候选记录“本轮适用并同步实施”“产品语义不同而不适用”或“需要用户决定后另行实施”及证据；用户点名、截图或历史回归涉及的页面也要列入。
- 专属状态机、DTO、权限或流程只说明领域语义应私有，不能直接推出所有交互原语都不能共享；逐层分开判断。
- 只有一个真实消费者或语义未稳定时保留私有实现；未来消费者、视觉相似或目录整齐都不能作为提前公共化理由，不预建 Registry、配置开关或空扩展点。

### FE-011 公共机制与消费者领域状态分离

- 公共层只拥有跨消费者稳定的机制、生命周期、协议、无业务含义状态和默认安全边界；消费者拥有产品流程、活动对象、领域数据、权限、持久化、上游调用和文案。
- 公共 API 让消费者传入或回调自己的领域操作，不读取兄弟应用私有全局状态、不复制 DTO，也不要求迁入同一业务状态机。
- 修改公共能力前核对当前契约、全部登记消费者和不适用项；破坏 API、改变默认行为、移除消费者或上收私有状态时记录迁移和退出条件，不能以“重构”静默改语义。
- 公共化后退出重复私有实现、失效选择器、旧入口和竞争文档；产品特化若保留，必须有独立语义和所有者。

### FE-012 公共能力必须有可发现的当前契约

- 采用项目为每项公共能力维护可发现的唯一当前契约，至少包含稳定 ID、所有者、源码/API、公共层职责与非职责、真实消费者、不适用项、接入方式、破坏性变更条件和验证边界。动态 `run`、截图、日期化结果和实施过程留在工作项或 proof，只由契约链接。
- 变更前读取契约；新增消费者或适用性变化时同一变更更新契约和反向消费者关系。契约缺失或与源码冲突时，以当前源码和产品事实纠偏，不能按旧工作项或记忆扩散。
- 开发宿主规则与能力契约不放进浏览器、安装包或运行时静态交付目录；入口只放稳定门禁和发现路由，API 与消费者事实由能力所有者维护。

### FE-013 完成判断从需求和消费者反推

- 验收矩阵从用户原始页面、动作、状态和全部适用消费者生成，不能从修改文件列表倒推；原缺陷入口和操作序列必须真实回归，公共能力至少覆盖各不同消费者状态机的代表路径。
- 结构检查证明公共 API、资源接线、登记消费者和禁止旧私有符号一致，但只能称自动检查；真实入口、状态变化、最终 DOM、控制台和截图按测试与 `FE-003` 执行。
- 任一适用消费者未接线、原页面未回归、截图未形成、领域状态未核对或旧私有实现仍竞争时，不得说“已公共化/已闭环/全部覆盖”；报告完成范围、缺口、风险和待决定项。

### 公共能力产出边界

- 交付至少说明稳定原语、消费者矩阵、所有权/API 边界、迁移/退役、契约更新、自动检查和真实验证边界。
- 不为建立登记而批量改造既有公共组件；首次登记发现漂移时只记录事实，并修复当前目标明确覆盖的对象。

## 页面入口

### FE-014 物理 HTML 是默认唯一页面地址

- 传统多页或服务端静态目录交付的独立页面，默认只使用真实存在的物理 `.html` 地址。没有外部契约、框架硬要求或用户决定时，不得增加无后缀、尾斜杠、目录默认页、Controller redirect/forward、history fallback、额外静态资源前缀或其他别名；例如框架已从 `classpath:/static/` 交付页面，就不再顺手增加 `/static/**` 页面地址。
- 部署单元明确要求 `http://IP:端口/` 直达产品时，根 `/` 可作为唯一宿主例外并重定向到一个规范物理首页；不得生成第二份 HTML，不得扩成 `/index.html`、业务无后缀、尾斜杠或目录页，目标首页仍走同等服务端鉴权。
- 不能只查显式 `ResourceHandler`；框架默认映射、自动装配或宽泛 classpath 位置若仍能从额外前缀交付同一资源，必须在组合根收紧/拒绝，并用当前构建实际请求证明不可达。
- 新增、移动、重命名或删除页面前必须列出全部生产消费者，同步导航、登录回跳、默认首页、浏览器自动打开地址、静态资源处理器、鉴权范围、功能事实和可执行检查；物理资源、展示 URL 和鉴权 URL 不能各自成为真源。
- HTML 与 CSS、JavaScript、字体、图片等子资源按真实安全责任分别处理。受保护 HTML 必须在服务端返回正文前鉴权；非敏感子资源可公开，业务 API 按自身协议鉴权。前端隐藏页面不能代替服务端鉴权。
- 除根入口外，只有已发布外链、书签、第三方回调、SEO、反向代理、框架路由或其他可定位消费者确实依赖别名时才保留；例外记录唯一规范地址、兼容期限/退役条件、鉴权等价性和消费者验证，不得以“更好看”“更稳定”或“以后可能需要”为依据。

### 页面入口产出边界

- 入口变更交付给出物理 HTML 清单、生产消费者矩阵、根入口及唯一目标、鉴权/公开资源边界、已删除别名和残留扫描结果。
- 历史 proof 和日期化审计快照保留当时 URL 事实，不为当前入口统一而改写历史记录。
