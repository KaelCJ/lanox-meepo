# 约束文本质量审计

## 审计边界

- 审计对象是用户以绝对路径指定的一个或多个 Markdown 文件，或用户在对话中直接给出的待审文本；只读审计，不修改、不迁移、不删除文件。
- 只判断表达是否承载可辨认的信息或约束，以及是否存在生成残留。
- 不判断事实真伪、专业结论、方案优劣、文档是否应当存在、内容归属、路由、生效方式或执行结果。
- 审计单位是句或条目；需要上下文才能判断时读取相邻内容，但只报告具体问题，不做全文重写。

## 核心规则

1. **删掉判据**：对每个审计单位问——删掉它，能否说出一个具体任务里 Agent 会因此做出的不同行为（错误判断、越权、错误声称、走错路径）。说得出 → 保留；只能说“确立基调、理念、完整性、严谨性” → 列为删除候选。
2. **否定句承重验证**：否定句和显式反例是承重结构，不是修辞。为其保留需补出真实来源（发生过或可指认的误判）；预防性罗列没有来源的假想误判 → 列为删除候选。例外：涉及凭据、越权、不可恢复操作、外发提交等高损失边界的否定句默认保留，只标注“来源未记录”，不列为删除候选；其余靠来源通过审计的否定句，处理建议中加一条——把来源一句话写入正文或工作项，使下次审计不再重问来源。
3. **生成残留句式清单**：代码块、行内代码和引号内样本先豁免。强信号单发命中且补不出具体误判场景 → 列为删除候选；弱信号单发只标注，同段再命中其他句式或规则 1、2 时升级为删除候选：
   - R3a（强）空泛拔高：用宏大背景、趋势或愿景包装普通陈述，却不增加具体对象、条件、责任或可验证结果；
   - R3b（强）creed 句（“既服务 X，也 Y”）；
   - R3c（弱）四连及以上动词（“共同形成、验证、沉淀和复用”）；
   - R3d（弱）目录复述（一句话重述下文标题内容）；
   - R3e（弱）无对应真实事件的防御性对冲（“除非……否则不假定……”）。
4. **结构性承重**：标题、导语、过渡和定位说明按其是否帮助识别对象、范围、顺序或关系判断；有实际作用则保留，删除后不影响理解则列为删除候选。

## 审计方法

1. 读取用户指定的每个绝对路径文件，或接收用户在对话中给出的待审文本；读不到的如实报告，继续其余输入。
2. 多个输入内容相同，或明确为同一正文的镜像、引用时，只审正文一次，并在输出中列明共同受影响的输入；无法确认关系时分别审计。
3. 逐个审计单位过核心规则 1–4；对每个删除候选补做反事实：删除后是否会损失信息、约束、结构关系或必要语境；会则改列为改写候选并说明。
4. 汇总输出；不因句子属于用户既有风格而豁免，也不把风格偏好写成问题。

## 输出

- 第一行总体判断（该文件质量是否合格、主要问题类型）。
- 问题清单：每项含行号、最小原文摘录、命中的规则编号（句式命中精确到 R3a–R3e）、一句话原因、处理建议（删除 / 改写 / 保留）。只列问题，不重写全文。
- 报告读不到的文件，以及因内容相同或明确镜像、引用关系而合并审计的输入；对话内文本的行号按文本块内相对行号标注。
