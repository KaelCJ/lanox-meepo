# API 安全审计目标

本文件定义阶段 4 的审计目标，不替代 `SKILL.md` 规定的 API 分母、保护链和方法调用图。先完成前三阶段，再把下列目标逐项投射到每个 API 的真实执行图。

## 通用判定方法

对每个适用目标记录：受保护资产、当前主体、目标对象、不可信输入、source、sink 或副作用、安全不变量、实际控制、覆盖分支、绕过反例、证据位置、状态和影响。

风险可以由 API 契约、入口配置、保护链、方法调用、数据流、控制流、返回映射或业务副作用中的任一处产生。不得只搜索漏洞关键词，也不得只检查某个固定层级。

## 1. 暴露面、契约与接口意图

- API 是否确实应该暴露在当前网络、网关、版本和方法范围；调试、管理、废弃或内部入口是否意外公开；
- path、query、header、cookie、body、multipart、消息和响应字段的类型、必填、范围、格式、默认值、嵌套和数组边界是否明确；
- `Object`、`JSONObject`、`JsonNode`、无界 `Map`、动态字典、原始 JSON、`any`、未约束泛型和 Entity 直绑是否造成查询控制、mass assignment、敏感字段写入或内部字段外泄；
- 路径、操作名、出入参和调用方表达的能力是否与实现、副作用、文档和最小必要原则一致；
- 客户端是否能够指定本应由服务端决定的用户、租户、归属、角色、状态、价格、审批结果或执行目标。

## 2. 身份认证与会话

- 匿名是否为明确设计；令牌、会话、签名或凭据是否完整验证，失败是否默认拒绝；
- 身份来源是否可信，是否可能被请求字段、转发头、缓存、异步消息或下游返回覆盖；
- Cookie 认证是否处理 CSRF，Webhook 是否验证签名、时效和重放；
- 登录、刷新、登出、重置、授权码交换、凭据签发和会话失效是否绑定正确主体并具有安全生命周期。

## 3. 功能级授权

- 当前主体为什么能调用该能力，角色、权限、scope、组织或策略是否命中当前方法和业务动作；
- 管理、审批、导出、批量、代办、高价值变更和其他敏感能力是否只有认证而没有功能授权；
- 管理员、系统任务、服务账号和内部调用旁路是否有明确策略和最小范围，而不是隐式跳过。

## 4. 对象、租户与关系授权

- 请求指定、间接解析或二次查询得到的目标对象属于谁，当前主体为什么能读写它；
- owner、tenant、org、workspace、ACL 或等价约束是否实际进入查询、写入、缓存键、外部请求或副作用；
- 是否只校验对象存在、只按请求 ID 查询、先取全量后过滤、校验父对象却遗漏子对象，或后续更换目标 ID；
- 列表、搜索、统计、导出、批量、文件、关联对象、间接标识和错误差异是否产生对象枚举或跨域访问。

## 5. 字段授权、敏感信息与凭据

- 响应字段是否按主体和角色裁剪，更新是否使用允许字段列表，客户端是否能修改归属、权限、审批和其他受保护属性；
- 是否返回 Entity、内部标识、隐私、密钥材料、认证状态、调试信息或超出当前目的的数据；
- Token、Session、Cookie、API Key、密码、密钥、重置链接、授权码及等价认证材料是否被返回、下载、导出、记录或提供代签发能力。

认证材料属于独立最高优先级目标：

1. 只要出现在外部出参或可调用副作用中，就建立独立审计项；
2. 即使属于当前主体，也检查 API 意图、协议必要性、主体绑定、签发或读取方式、作用域、生命周期、撤销、最小披露和泄露后的滥用能力；
3. 输入允许指定用户、租户、账号、Session 或其他主体时，必须验证调用者与目标主体关系；
4. 能取得、签发、刷新或导出其他主体的认证材料时，判为重大安全发现，并继续确认是否可账户接管、权限提升、横向或跨租户扩散；
5. 不得因为登录/刷新接口通常返回 Token 而跳过，只能在完整证明标准协议语义和控制后判定相应目标。

## 6. 输入处理、注入与反序列化

- 不可信输入是否进入 SQL/NoSQL、表达式、模板、命令、脚本、LDAP、日志格式、解析器或动态字段名；
- 参数绑定、校验、规范化和编码是否发生在正确顺序，白名单是否覆盖嵌套对象和集合元素；
- 多态、动态类型、原始对象、反序列化回调和对象合并是否允许构造未预期类型或修改安全属性。

## 7. 文件、路径与内容处理

- 上传、下载、预览、解压、转换和删除是否约束路径、对象归属、大小、数量、类型和内容；
- 是否存在目录穿越、符号链接、压缩炸弹、覆盖、任意读取或执行；
- 文件名、Content-Type、扩展名和实际内容是否被错误信任，下载响应是否泄露路径或敏感元数据。

## 8. 外部请求与依赖消费

- 用户可控 URL、主机、协议、重定向、DNS、代理和请求头是否形成 SSRF 或访问内部资源；
- 下游响应、Webhook、第三方状态和签名结果是否被安全验证，失败、超时、重试和部分成功是否安全；
- 向外部系统发送的数据和凭据是否最小化，是否可能跨租户、跨环境或进入不可信目的地。

## 9. 业务流程与副作用

- 创建、修改、删除、审批、支付、通知、授权、生成凭据和其他高影响动作是否符合状态机、顺序、额度和主体约束；
- 是否可跳过步骤、重复执行、越级操作、替换目标、绕过确认或滥用批量能力；
- 幂等键、重放防护、事务、并发、竞态、补偿和部分失败是否保持业务与安全不变量。

## 10. 资源消耗与可用性

- 分页、批量、搜索、导出、上传、解压、复杂查询和外部调用是否有数量、大小、深度、频率、超时和成本边界；
- 限流是否按真实主体、租户、客户端和高风险动作生效，是否可通过路径、方法、标识或并发绕过；
- 异步任务、重试、缓存穿透和下游放大是否允许低成本触发高成本工作。

## 11. 缓存、异步、消息与上下文

- 缓存键是否包含必要主体、租户、权限版本和数据范围，缓存内容是否可能被其他主体复用；
- 安全上下文进入异步任务、事件和消息后是否保持可信，消费者是否重新验证目标和权限；
- 二次读取、延迟执行、重试、死信和补偿是否在状态变化后继续使用过期授权。

## 12. 错误、日志、响应与配置

- 不存在与无权限响应是否泄露对象存在性，异常、堆栈、SQL、路径、内部类型或下游响应是否外泄；
- 日志、指标、trace 和审计记录是否包含凭据、隐私或跨租户内容，是否可被不可信输入伪造；
- CORS、缓存头、安全头、内容类型、下载头和调试配置是否匹配当前 API；
- 多版本、影子路由、白名单、默认配置和资产文档是否漂移，导致旧接口或另一条链路绕过当前控制。

## 目标状态门槛

- `通过` 必须引用保护链和方法调用图中的端到端证据；没有发现关键词不构成通过。
- `失败` 必须给出从触发条件到响应或副作用的可定位路径；无需实际利用或读取真实数据。
- `未确认` 必须指出断点、缺失事实及其阻止的安全结论；不能降级为低风险。
- `不适用` 必须说明为什么该目标在当前 API 的契约、意图和执行图中客观不存在。
- 同一目标存在已证实失败和其他未知分支时，以 `失败` 作为目标主状态，但仍在未确认事实清单中逐项保留、计数未知分支；不能用已失败替代继续审计。
- 业务例外、内部使用、管理员需要或风险接受不属于 `不适用`；必须按 `SKILL.md` 的人工排除门禁处理。
