# 续接 Session

把一个 context 打爆、无法继续的旧 Claude session 蒸馏成紧凑上下文，在新 session 里接着干。

## 硬边界

- 触发：用户在新 session 里调用 `$nest-session-resume <旧 session 标识>`，或明确要求按本 SKILL.md 续接某个旧 session。标识可为 session 标题、标题片段、关键词或 `local_<uuid>` 形式的 session id。
- 只读旧 session：只用 CCD session 管理 MCP（`list_sessions`、`search_session_transcripts`、`list_events`、`get_session`）读取目标 session 的元数据与 transcript。不调用 `send_message` 给旧 session 发消息，不归档、不重命名、不删除、不修改旧 session 任何状态。
- 不落盘：不写 handoff 文件，不动 git 索引或工作树，不写 `.workspace-assistant`、`.claude`、`.logs` 或任何仓库文件，不更新 memory / `MEMORY.md`。蒸馏结果只作为当前 session 的上下文存在。
- 不读爆新 session：旧 session transcript 可能很大。按页有界回读，页内就地蒸馏、只留用户原文与抽样结论，不为"读全"而无界翻页。
- 不臆造：蒸馏只基于读到的 transcript 事实；读不到的部分如实标注"未读"，不补脑、不外推。

## 预算与状态账本

每次调用只在当前上下文维护一个简短账本，不写入文件或其他持久状态：

- **读取预算**：最多 6 个已接受页面、180 个事件、累计 32,000 个 transcript 文本字符；单页软上限 6,000 字符。仅在响应明确提供 token/字节计数时使用该计数；否则用可见文本字符数作等价预算，不猜测隐藏 tokenizer。所有响应（包括因过大而重取或放弃的页面）都计入字符预算；重取同一页不增加已接受页面数，但不得借重取绕过总预算。
- **摘要预算**：续接摘要目标不超过 6,000 个可见字符。用户原始消息是最低保留线；若仅用户原文就超过预算，不截断或改写用户原文，压缩 assistant/tool 结论并在摘要中标记“摘要超预算”。
- **账本字段**：`页数`、`事件数`、`文本字符数`、最近页的最晚/最早事件 uuid、下一页 `before_uuid`、已读时间范围（无时间字段则标“仅 uuid”）及未读原因。字段无法核对时记为“未知”，不得用记忆补齐。

## 步骤

### 1. 定位目标 session

1. 解析 `$ARGUMENTS` 取标识：先 trim，再去掉可选的前导 `:`（兼容 `/nest-session-resume : xxx` 与 `/nest-session-resume xxx` 两种写法）。标识为空时只追问一次。
2. 若标识形如 `local_<uuid>`，直接 `get_session` 取元数据确认。
3. 否则 `list_sessions`（`include_archived: true`，`limit: 30`），按标题子串不区分大小写匹配。唯一命中即用。
4. 多义或无命中时再用 `search_session_transcripts`（`query` = 标识，`include_archived: true`）按 transcript 内容进一步定位。
5. 仍不唯一时只追问一次：列出候选（标题 + 最后活动时间 + cwd）让用户选，不自行猜。

确认后记下：session id、标题、cwd、最后活动时间。

### 2. 有界回读 transcript

用 `list_events` 从尾部往回读，`most recent last`：

- 首页：`list_events(session_id, limit: 30)`，取最近事件。
- 向前翻页：`list_events(session_id, limit: 30, before_uuid: <上一页最早事件的 uuid>)`，逐页往回。
- 接受页面前先核对顺序和 uuid：事件应保持 `most recent last`，页面内 uuid 不重复；下一次请求的 `before_uuid` 必须等于上一页已接受页面的最早事件 uuid。发现重复、游标缺失/未前移、顺序或响应是否完整无法确认时立即停止，保留已读范围并标注未读边界，不猜下一页。
- 单页超过 6,000 个文本字符或含大段文件全文/长输出时，在同一游标用 `limit: 15–20` 重取；若仍超过单页上限，只提取用户消息、事件元数据和可定位的结论性片段，标记其余为“未读/未确认”，不要继续向前翻页。
- 回读上限：默认累计不超过 6 页（约 180 事件）或 32,000 个文本字符；达到任一上限即停止。重取页不得突破上限。
- 停止条件（任一命中即停）：
  1. 已读到 session 最初的用户原始请求；
  2. 最近 2–3 页已能完整还原"当前任务状态 + 下一步"且已收集到原始用户请求。
- 达到上限仍未到起点：停止回读，在摘要里如实标注"更早 N 轮未蒸馏，需要可继续往前拉"，并写出最后一个已确认的 `before_uuid`；不无界续读。

### 3. 页内就地蒸馏

每读一页立即处理，不在工作记忆里堆原始大段：

- **用户输入逐条保留**：把读到的每一条 user/human 消息原文（或近原文，仅修整明显笔误）按时间顺序收进"用户原始意图与关键输入"。用户输入量小、保留成本低而价值高，是蒸馏的最低保留线。
- **Claude 产出智能抽样**：assistant 的推理与 narration 压成结论性短句（决策、计划、判断、承诺、修正）。工具调用与工具结果只留"工具名 + 目的 + 关键结论"，丢弃大文件全文、长命令输出、完整 diff、完整日志、完整 stack trace；保留的结论必须忠实于原结果，不得夸大或改写。
- **区分事实与未决**：明确什么是已确认结论、什么是还在进行或待用户决定。

### 4. 产出续接摘要

按下列结构组织，条目按需增减，缺的留空或标注"无"：

```
# 续接上下文：从 <旧 session 标题>

## 来源
- Session: <标题>  id: <...>  cwd: <...>  最后活动: <...>
- 蒸馏范围: 最近 <n> 轮 / <起止时间近似>
- 未读: 更早 <m> 轮未蒸馏（如需可继续往前拉）
- 回读账本: <页数>/<6> 页，<事件数>/<180> 事件，<文本字符数>/<32,000> 字符；摘要 <字符数>/<6,000> 字符（是否超预算）
- 游标与已读范围: 最晚事件 uuid <...>；最早已读事件 uuid <...>；下一页 `before_uuid` <.../无>；时间范围 <.../仅 uuid/未知>

## 用户原始意图与关键输入（逐条保留）
- <原文/近原文，按时间顺序>

## 当前任务状态
- 目标：
- 已完成：
- 进行中：
- 未决/待决：
- 下一步：

## 关键决策与结论（抽样）
- <结论性短句，标注来源轮次近似>

## 重要约束与边界
- <从上下文提取的硬约束，如项目规则、Git 边界、运行端口、测试禁令等>

## 需要继续的具体动作
- <可立即执行的下一步>
```

### 5. 压缩/恢复重读门禁

- 触发条件：在已有蒸馏状态准备继续使用时，当前可见消息明确说明发生了上下文压缩、会话恢复/接续或摘要被截断，**或**无法逐项核对目标 session 身份、读取账本、游标/已读范围、摘要完整性或用户确认状态。不要假设存在不可见的内部压缩信号；只依据可见证据，无法核对本身就触发门禁。
- 触发后先暂停续接和原任务推进：重新读取本 `SKILL.md` 全文（正文不可读则停止），再用 `get_session` 核对同一 `session id`；身份不一致时重新定位，不把相似 session 当成同一目标。
- 丢弃无法核对的旧页账本、摘要事实和 `before_uuid`，从目标 session 尾页按本 Skill 的同一预算重新 `list_events`，逐页重建账本。不得从记忆中的游标续读，也不得把先前“已读”当作已确认事实。
- 重读完成后重新展示摘要；先前的用户确认不自动继承。用户再次明确确认前，不注入摘要、不执行原任务。若重读仍无法完成或预算耗尽，报告准确的未读/未确认范围并停止。
- 同一调用最多进行一次恢复重读；第二次仍无法确认时交给用户，不循环重试。

### 6. 先展示确认，再注入

1. 把续接摘要作为当前回答展示给用户，并明确说明：这是蒸馏结果、未读部分已标注、确认后即作为本 session 续接上下文。
2. 不经确认不擅自推进原任务，等用户确认或修正。
3. 用户确认后：本摘要即已落在当前 session 上下文里，直接按"下一步"继续工作，无需再写文件或再读旧 session。
4. 用户要求修正时：按修正调整后再次展示，直到确认。

## 边界与例外

- 当前 session 无法续接自己：`list_sessions` 排除当前 session，属正常保护，不要绕过。
- 旧 session transcript 已不存在或不可读：停止并如实报告缺口，不编造摘要。
- 标识匹配到正在运行的别的 session：只读 transcript，不打断对方运行，不发消息。
- 一次只续接一个旧 session；用户要合并多个 session 的上下文时逐个蒸馏后再整合，仍只注入当前 session。
- 蒸馏不替代当前真源：摘要里涉及的工作项、规则、源码状态，继续工作时仍以仓库当前事实为准，必要时回到对应权威入口核对。
