# Agent 入口产出规则

当前双宿主契约：`AGENTS.md` 是入口规则的唯一正文所有者；同目录 `CLAUDE.md` 是 Claude 宿主的薄包装，正文只写 `@AGENTS.md`。不复制共享正文，不在 `CLAUDE.md` 维护第二套规则。当前没有宿主专属入口块；以后若出现宿主差异，必须先单独建立有证据的承载方案，不能直接在本契约下追加。

## 进入生产动作

1. 先确认用户已授权当前创建、修改、移动或删除范围；加载本 Skill 不扩大写入、清理、提交、发布或跨仓同步授权。
2. 定位目标工作空间根入口、目标目录的祖先入口链和当前双宿主文件；先解析 `CLAUDE.md` 的 `@AGENTS.md` 导入并只加载 `AGENTS.md` 正文一次。若发现旧的重复正文或真实宿主差异，先区分活动入口与历史/冻结资产，再决定迁移；保护既有未提交改动与 Git index，不把历史提交树当作当前状态。
3. 本 Skill 只负责 `AGENTS.md`、`CLAUDE.md` 及其模板和确定性辅助工具。
4. 用户只要求检查、Review、诊断或提出建议时停止写入。

## 判断入口角色

写入前明确记录目标文件的角色、消费者和作用域：

- 根项目入口：只保存项目专属、跨任务稳定且首次相关动作前必须知道的增量约束。
- 目录入口：只保存相对祖先链新增的局部约束，不复制根入口或 SessionStart 正文。
- 模板或生成资产：保存稳定结构与占位符，不冒充活动入口或当前项目事实。
- 运行时 Agent 资源：只有运行时消费者明确读取时才使用入口文件名；开发宿主规则不得放进静态资源、构建输出或交付包。
- 历史或冻结资产：保持原始事实；除非用户明确要求迁移或修复该资产，不按活动入口同步改写。

角色、消费者或宿主发现语义无法确认，且不同判断会改变文件位置或删除范围时，停止受影响写入并报告缺口。

## 执行双宿主同步契约

1. 默认在同一活动目录同时维护 `AGENTS.md` 与 `CLAUDE.md`；创建、移动、重命名或删除其中一个时，同步处理另一个。
2. `AGENTS.md` 保存完整共享规则；`CLAUDE.md` 必须使用同目录相对导入 `@AGENTS.md`，不得复制正文、反向导入 `CLAUDE.md`、使用符号链接或追加未经确认的宿主专属段落。
3. 修改共享规则时只修改 `AGENTS.md`，再用配对校验器确认 `CLAUDE.md` 仍是纯导入包装；创建、移动、重命名或删除时同步维护导入目标。
4. 发现既有宿主差异时，不得静默丢弃或把差异扩大到所有入口；先按历史/冻结资产与活动入口分流并报告，再由用户明确迁移策略。

## 选择正确承载层

- 入口保留稳定行为结论、适用对象和必要路由；背景、完整流程、判断树和大段示例放入对应 Skill、Rule 或权威文档。
- SessionStart 只保留首次动作前必须知道的最短边界和按需入口，不展开任务目录、Skill 方法或项目专属正文。
- 日期化 proof、当前模型或版本清单、动态状态、历史过程和单次整改事实放入工作项、运行证据或真实所有者；入口只保留如何定位和不能错误推出什么。
- 父入口已经生效的规则不在子入口复述；机械可判定的配对、同步和引用问题交给脚本验证，入口只保留 Agent 行动前仍需理解的约束。
- 不直接修改 `target/`、`build/`、`dist/` 等生成目录中的入口副本；修改源码所有者并按项目构建流程重新生成。构建产物中的孤儿入口需要清理时，先核对准确来源和清理授权。

## 设计与精简入口正文

1. 创建、改写或删除规则前，先明确它要阻止的真实失败、适用动作、当前消费者、必须行为、禁止边界、目标所有者和首次相关动作前的发现路径；不能只做文字增删。
2. 信息结构服从语义关系：相互独立的规则使用小标题和短列表；只有多组对象需要按同一字段精确比较或映射，且单元格能保持简短时才使用表格。不得为视觉整齐把长段独立规则塞进表格。
3. 入口保留稳定行为结论和完成发现所需的最短路由；完整方法可以归入 Skill、Rule 或权威文档，但目标正文尚未建立、不可达或触发条件不准确时不得先删原文。
4. 删除或压缩前执行反事实：假设候选正文不存在，从新 Session 的首次相关动作开始核对 Agent 是否仍能及时找到唯一规则并保持原行为、安全和授权边界；任一项不能成立时先重新设计承载。
5. 不因正文较长、属于“方法论”或与模型常识相似就机械删除；精简的判据是职责唯一、可发现且行为不丢失，不是字数更少。

## 创建入口

1. 从祖先链和目标子树提炼真正的局部增量；没有局部增量时不创建空入口或根规则副本。
2. 需要新项目根结构时，使用 `assets/AGENTS.md.template` 生成共享正文，使用 `assets/CLAUDE.md.template` 生成只含 `@AGENTS.md` 的宿主包装；用当前项目事实替换全部占位符。
3. 同时写入双宿主文件，检查标题、相对路径、Skill 名称、引用目标和作用域。
4. 确认文件位置不会意外进入静态交付物、安装包、历史快照或另一个宿主发现链。

## 修改、迁移或删除入口

1. 解析并校验 `CLAUDE.md` 的导入目标及 Git 状态，区分既有用户差异、本轮共享改动和历史/冻结资产；共享正文只从 `AGENTS.md` 加载一次。
2. 把仍有价值的规则迁到 `AGENTS.md` 后再删除 `CLAUDE.md` 中的竞争正文；迁移后保留唯一的 `@AGENTS.md` 可发现路由，避免断链。
3. 移动或重命名 Skill、Rule、Hook 或入口时，只更新活动消费者和当前权威说明；历史冻结包、哈希清单和事件原文默认不追写。
4. 删除静态资源或构建输出里的错误入口前，确认运行时没有读取该文件名；仍有局部开发规则时先上收到拥有该资源的源码模块入口。

## 验证与汇报

1. 对本轮所有活动入口目录运行（历史测试 proof 等明确排除项单独列出）：

```text
python .agents/skills/nest-rule-entry/scripts/validate_entry_pairs.py --root . --exclude .logs/actual-test
```

2. 修改 SessionStart 或宿主接线时，分别执行 Codex 与 Claude 的真实 handler，比较输出与唯一正文；handler 通过不能冒充新 Session 已发现或遵守。
3. 检查活动文档、命令和配置不存在旧 Skill 名称或失效路径；历史冻结资产和测试 proof 的保留命中单独说明。
4. 汇报本轮同步目录、导入包装、迁移或删除内容、机械验证、未执行的新 Session 验证及回退方式。
