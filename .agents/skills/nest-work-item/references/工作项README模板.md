# 工作项 README 模板

根 README 是工作项的记忆摘要、Human Review 和续接入口，在工作项标题下只使用四个固定 H2：

- `记忆摘要`：压缩形成当前状态所需的历史因果、关键纠正和被替代结论；不是按日期追加的流水账。
- `当前简介`：只说明工作项现在是什么、解决什么问题和当前形态；不复述历史。
- `当前停点`：保存恢复执行所需的当前目标、已完成、未验证、下一步和阻塞。
- `工作项宪章`：保存该工作项独有且长期有效的定位、责任、边界和决策原则；通用工作方法不得写入。

固定文件路径和加载顺序由 `nest-work-item` 维护，README 不建立通用导航。生命周期、优先级、时间、类型、产品和物理入口只在工作项 JSON 索引维护；需求、方案、执行、测试和历史正文由各自文件拥有。

创建路径使用以下最小结构并按当前事实填写；不知道的内容标明“待确认”或“待补充”，不要编造：

```markdown
# <ID> 工作项名称

## 记忆摘要

<一至三段，只保留理解当前形态必需的关键上下文>

## 当前简介

<当前定位、目标、范围和已经形成的形态>

## 当前停点

- 当前目标：
- 已完成：工作项骨架、原始需求和索引记录已创建
- 未完成与未验证：认知拉齐、正式需求、方案、执行和测试尚未建立
- 下一步：根据后续明确动作进入建档、需求、方案或执行
- 等待或阻塞：

## 工作项宪章

- 定位与责任：
- 稳定边界：
- 决策原则：
```

只固定这四个 H2，不再强制细分结构。“当前停点”固定使用五个字段；“工作项宪章”默认使用语义标签列表，只有该项确有多个独立且长期稳定的治理域时才增加更细标题，不创建空标题。关联文件或其他工作项只有在承载独有责任、边界或事实所有权时才就近链接，不单设导航区。

后续动作只更新真实变化的部分：记忆摘要重写并压缩，不累加过程流水；当前简介保持现在时；当前停点不得把计划写成已完成，也不得把局部检查写成整体通过；宪章只在用户决定或已核实的长期边界变化时修改。
