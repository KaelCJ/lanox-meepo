# 执行方法

`执行/执行步骤.md` 在方案明确后产生，把方案拆成可以逐个交给 Agent 的原子任务。Agent 恢复当前有效依据后，读取当前任务及其必要引用即可动手，不再自行重选方案。

## 恢复与纠正

开始或恢复实施、上下文压缩后继续、接手以及收到影响当前任务的纠正时，先完整回读工作项 README、当前任务所属的有效方案正文、当前步骤和相关验证依据；方案明确必读的契约、样例等一并读取。压缩摘要只用于定位，不能替代这些正文。其他路线、历史和研究材料按需加载，不在每个命令前重读全套文件。

恢复后应能确定当前目标、必须遵守的做法与不做项、最新纠正、当前步骤和完成依据。关键内容缺失或冲突时，先补齐或澄清受影响部分；已有授权和明确决定继续有效，不重复向用户确认。

当前任务涉及跨边界交互时，按 [方案方法](方案/方案方法.md) 确认所需时序图并读取对应 `.puml`；不能因方案正文未提时序图而跳过。缺图、图已过期或图文冲突时，在已有授权内先补齐受影响的设计，再实施该链路；只缺渲染预览时按时序设计方法记录限制，不阻塞已有明确依据的实施。

用户纠正或事实推翻当前决定时，在继续相关操作前按 [更新工作项方法](../流程/更新工作项方法.md) 记录纠正，并传播到受影响的认知、需求、方案、步骤和验证依据。明确什么旧理解被替代、哪些已完成产物需重查或返工，将相关步骤重新打开，旧验证结论标为待重验或失效；无影响的内容不改。只有用户才能决定的歧义才询问，不以一句“理解了”代替实际更新。不受影响的已授权工作可以继续。

## 原子拆解

一个任务只完成一个结果。按以下问题判断是否已经拆到合适粒度：

1. 能否用一句话说清“在什么对象上做什么，得到什么结果”？
2. 新 Agent 能否根据任务给出的准确位置和引用直接开始？
3. 是否还包含可以单独完成、失败或重试的另一件事？有则拆开。
4. 拆开后是否会留下不可运行、不可理解或无法续接的中间状态？有则合并。
5. 完成后能否停下来，把下一件事留给下一个任务？

不要按文件数量、技术层、命令数量或验收项机械拆分。一个结果需要同时修改多个文件或多个层次时仍是一个任务。任务仍要求 Agent 选择方案、判断范围或补充产品决定时，说明方案尚未完成，不能把这些决定留给执行 Agent。

## 任务内容

每个任务只写执行所需的信息：

- 编号和一句话标题；
- 准确的操作对象，例如模块、文件、符号、接口、数据或文档位置；
- 当前方案、开始前必须读取的局部事实或前置任务；共同方案可在文件开头引用，任务只补充差异；
- 具体动作；
- 动作完成后得到的直接结果；需要验证的，引用相关验证依据与观察点，不复制正文。

不为任务另建 AC、验收矩阵、背景复述或固定字段表。直接结果就是本任务的结束边界；工作项整体是否满足需求，由需求和测试材料判断。

默认使用一行任务：

```markdown
- [ ] S01 在 `<准确位置>` 对 `<对象>` 执行 `<具体动作>`，得到 `<直接结果>`。（先读：`<必要引用>`）
```

没有必要引用时省略“先读”。一句话放不下时，只在该任务下补充完成动作必需的细节，不展开工作项背景。

## 执行

`执行/执行步骤.md` 标出唯一当前任务。恢复有效依据后，按当前任务补充必要局部事实，连续做到直接结果出现；新发现的独立工作另列任务，不悄悄扩大当前任务。

需要验证时按 [测试验证方法](测试验证方法.md) 比较实际产物与事前依据。完成后勾选并记录实际结果及位置、相应验证结论或未验证边界，更新 README 当前停点与相关事实，再进入下一已授权任务。勾选表示本任务直接结果已出现，不自动代表工作项整体通过；失败或结果尚未出现时保留未完成状态和真实恢复入口。
