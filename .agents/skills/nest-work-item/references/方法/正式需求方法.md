# 正式需求方法

用于创建和维护 `需求/需求.md`。

以原始需求、已确认的共同理解、核实后的当前事实和适用约束为输入，描述要解决什么、为什么解决以及外部可观察结果，不编写实现设计。

按复杂度覆盖：

- 背景、目标和成功标准；
- 范围与不做项；
- 用户或系统场景及功能要求；
- 关键边界与失败场景；
- 适用的非功能要求、依赖和假设；
- 验收标准和待确认项；
- 需求与来源的关系。

需求应明确、可判断并能落到可观察验收。已有系统改造要区分当前行为与目标变化；未确认的 Agent 推断保留为假设或待确认项。

只有后续材料需要稳定引用时才使用 `REQ-*`、`AC-*`。技术方案、文件设计和执行步骤分别进入 `方案/` 与 `执行/`。
