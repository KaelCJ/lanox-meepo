# 测试验证方法

`测试/测试验证.md` 维护事前验证依据和当前验证结果。建立依据、实际验证、更新结果或 Review 验证材料时读取本方法；具体操作遵守当前项目和产物对应的专业方法。

## 验证依据

实施前根据当前需求和方案，写清用什么判断产物正确、如何观察；开始验证前核对这些依据仍然有效。已有明确标准时直接引用，不复制为另一份正文。先建立本次所需内容，不为形式完整制造样本、表格或目录。

- 说明验证对象、真实入口、必要前置条件和操作方式，以及需要看到的结果、允许差异和明确失败表现。
- 按产物选用有助于判断的参照：代码可用伪代码、核心流程和输入输出；提示词、文档可用 Demo 或适用的专业方法论；图片等使用对应专业参照。不要求每项工作具备全部形式，也不用字面相似代替专业正确。
- 说明参照来源、具体约束什么、哪些允许发挥，以及是用户已确认、既有标准还是 Agent 拟定。Agent 草案不能冒充用户认可；影响目标或关键取舍的不确定项先澄清，授权范围内的实施细节自行完成。
- 参照正文由现有真实位置或所属方案拥有，此处维护引用及比较方式；短小且仅用于验收的预期可以直接写在此处。

## 实际验证与比较

按事前方式检查本次实际产物，并逐项说明符合、偏差或未验证。验证产品行为时必须从真实入口走适用的完整流程，核对最终页面或业务结果；参考样例不能替代真实依赖和实际产出。文件、文档、图像等按对应专业方法检查最终成品及其必要使用效果。

对方向不确定、返工成本高或批量产出的工作，先完成一个有代表性的最小完整样例，核对方向再展开；不把所有微小修改都变成样例审批。关键验证失败时先修复并重验，再继续依赖该结果的工作；不受影响的已授权工作可继续。

## 结果与维护

记录检查对象或产物版本、实际操作、预期与实际差异、结论和可定位证据。未执行、因条件缺失无法验证、验证失败和验证通过分别如实表述；编译、格式、链接和索引检查只证明各自检查范围，不能据此宣布真实行为通过。

更新当前结果时保留仍有效的验证依据，不能因产物不符合而反向放宽标准。需求或方案确实改变时，先记录变更依据，再调整相关验证预期；受影响的旧通过结论标明失效或待重验。旧结果只保留有诊断或恢复价值的部分，不无限累加过程日志。

收尾时列明实际覆盖与未覆盖范围。步骤已实施、部分验证通过和工作项整体达标是不同结论，必须有相应证据。
