# 更新工作项方法

本方法用于把已经发生的需求确认、方案决定、实施结果、失败、测试证据和产出同步到已有工作项。它不替代任务本身的需求、设计、实现或测试方法论，只负责把事实写回正确所有者。

## 更新步骤

1. 盘点本次用户输入、Agent 实际动作、文件变化、命令结果、证据、失败和剩余事项；只更新真实变化的所有者：
   - 用户原话与 Agent 实际响应摘要：读取 [原始需求方法](../方法/原始需求方法.md)，更新 `需求/原始需求.md`；
   - 已确认理解、纠正和关键边界：读取 [认知拉齐方法](../方法/认知拉齐方法.md)，更新 `需求/认知拉齐.md`；
   - 已确认需求、范围和验收标准：读取 [正式需求方法](../方法/正式需求方法.md)，更新 `需求/需求.md`；
   - 当前有效技术决定：读取 [方案方法](../方法/方案/方案方法.md)，更新 `方案/方案.md`；需要设计当前空间与直接上下游的跨边界交互时，再读取 [时序设计方法](../方法/方案/时序设计方法.md)；
   - 执行任务、实际实施、失败和剩余步骤：更新 `执行/执行步骤.md`；只有需要创建或重组原子任务时才读取 [执行方法](../方法/执行方法.md)；
   - 当前验证结果与可定位证据：更新或创建 `测试/测试验证.md`；未执行就写“未执行”，新结果替换已经过期的当前结果，不编造测试或证据；
   - 工作项自身的独立产物：放入条件目录 `产出/`；产品产物保留在产品真实位置，工作项只记录必要链接，每个产物只有一个当前真源。
2. 读取 [工作项 README 模板](../工作项README模板.md)，压缩更新记忆摘要、当前简介和当前停点；宪章只在独有长期边界真实变化时更新。
3. 只修改受影响文件，不为完整度创建空记录，不在多个文件重复同一正文，不把计划写成已完成。
4. 更新索引 `updatedAt`，执行 `validate`，回读实际变更并报告已更新内容、未验证边界和下一步。

用户仅要求查看、说明或只读 Review 时不得使用本方法；发现的问题只有在用户另行授权整改或记录后才写入。
