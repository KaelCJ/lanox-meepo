# 只读 Review 方法

本方法用于只读 Review 已有工作项的需求、方案、执行或测试。

按 Review 对象只读取必要事实：

- **需求 Review**：读取 [正式需求方法](../方法/正式需求方法.md)、原始来源、认知拉齐、当前正式需求及其依赖的必要系统事实。
- **方案 Review**：读取 [方案方法](../方法/方案/方案方法.md)、当前正式需求和所审路线的方案；审查路线关系或整个工作项时读取各当前方案。涉及当前空间与直接上下游的跨边界交互或已有时序材料时，再读取 [时序设计方法](../方法/方案/时序设计方法.md) 和必要源码、配置、契约与运行事实。依据实际链路核对时序触发结论及每条链路对应的 `.puml` 内容；应出未出、旧图未同步或图文冲突均报告为影响相关方案可实施性的缺项，不能仅因正文未提图或没有目录而略过；只读 Review 不补图。
- **执行 Review**：读取 [执行方法](../方法/执行方法.md)、当前需求、相关方案、执行入口、工作区改动、未跟踪文件、命令结果、日志和现有证据；不得只依据步骤自述判断完成。
- **测试 Review**：读取 [测试验证方法](../方法/测试验证方法.md)、当前项目和宿主测试规则、当前需求或验收关注点、执行偏差及 `测试/测试验证.md`；对照仍有效的事前验证依据、实际结果与可定位证据，判断预期与实际的差异、结论支持范围，以及受需求或方案变更影响的旧结论是否仍然有效。

第一行给总体判断，其后只报告已证实问题、影响结论的证据边界和必要下一步；允许如实返回未发现问题，不为凑数量制造缺陷。

只读 Review 不创建或修改文件、索引、状态和产物，不同步当前 Session，不执行测试或整改。用户要求整改、持久报告或实际测试时，先结束 Review，再按新的授权处理。
