# 继续工作项方法

只读查看或说明时，仅读取当前问题所需材料并保持只读，回答后结束；只读 Review 读取 [只读Review方法](只读Review方法.md) 后按其处理。不因记录缺失而补写文件、回写索引或执行验证。

按用户本轮目标直接读取对应方法；目标未重述时从 README“当前停点”恢复。先加载方法再判断已有产物是否满足要求，不因正文自述“方案已明确”而跳过方法。

- **澄清或纠正共同理解**：读取 [认知拉齐方法](../方法/认知拉齐方法.md)。
- **形成或修改正式需求**：读取 [正式需求方法](../方法/正式需求方法.md)。
- **设计或修改方案、接口、架构、交互流程**：读取 [方案方法](../方法/方案/方案方法.md)。页面与服务端、当前应用与其他进程、服务或资源之间的协议、数据、顺序或可观察结果发生变化，均需判定时序图是否触发；同一仓库不等于同一运行边界。命中时读取 [时序设计方法](../方法/方案/时序设计方法.md) 并交付源图。
- **拆执行步骤或实施**：读取 [执行方法](../方法/执行方法.md)，先恢复当前有效依据。只要求拆步骤时不自动实施。
- **准备、实施或复核验证**：读取 [测试验证方法](../方法/测试验证方法.md)。

仅回补目标动作缺少的必要前置事实；以对应方法要求的内容、来源和完成判据判断，不以文件存在或文件名符合模板作为完成依据。历史布局中仍有效的材料直接复用，不因缺少标准路径重建或迁移。用户只授权方案时，完成方案后不自动实施；已授权连续推进时，步骤完成即进入下一必要动作。

写入路径中，原始需求缺失或本轮原话尚未记录时，按 [原始需求方法](../方法/原始需求方法.md) 补记；创建路径已写入的原话不重复追加。

用户要求整体补齐记录（建档）时，在已有身份和目录内依次处理原始需求、认知拉齐、正式需求、方案、执行步骤和验证依据，复用仍有效的材料，不初始化索引或分配编号。建档只建立记录，不实施方案、不运行验证；来源不足时记录缺失事实与受影响动作，只有需要用户决定或补充的信息才询问。

收到影响工作的纠正时，先按 [更新工作项方法](更新工作项方法.md) 同步受影响依据，再继续相关动作；每步完成、发生失败或需要交接时，同步实际结果和 README 当前停点，失败时保留现场和恢复入口。建档完成后回读各记录并报告待确认、未实施和未验证边界，不能将记录齐全写成需求已确认或方案已批准。

生产动作只执行用户当前授权的目标，不因“继续”或阶段转换自动获得发布、发送、迁移等外部副作用的授权。
