# 工作项路由

只给出 Skill 名或 R 编号且没有动作时，保持零写入并请求具体动作；仅讨论是否应该创建时，不进入创建路径、不写入。

识别当前请求，每次只选择当前意图对应的主方法：

- **创建工作项**：用户明确要求创建、新建、立项或登记工作项，且有可辨认的真实目标时，进入 [创建工作项方法](references/流程/创建工作项方法.md)；缺少目标时先澄清，不加载方法、不写入。
- **推进已有工作项**：查看、说明、需求、设计、实施、验证或补齐记录（建档），进入 [继续工作项方法](references/流程/继续工作项方法.md)。已有上下文能定位工作项时，不要求用户重述编号。
- **更新工作项记录**：Agent 已完成需求、方案、实施、验证或产出，需要把事实回写工作项时，进入 [更新工作项方法](references/流程/更新工作项方法.md)。
- **只读 Review**：进入 [只读Review方法](references/流程/只读Review方法.md)。

进入所选方法前，先读取 [索引与定位方法](references/索引与定位方法.md)。继续、更新或 Review 须先定位唯一工作项并完整读取根 README；创建无需先定位已有项。

主方法负责继续按需加载细粒度 reference；不要预读其他路径。明确的组合请求按顺序逐个完成，例如“创建并建档”先创建，成功回读后再继续。

已进入工作项实施或验证后，持续按 [继续工作项方法](references/流程/继续工作项方法.md) 推进；恢复、上下文压缩、交接或收到相关纠正后，先恢复当前有效依据再执行。步骤完成即回写，不等整个长任务结束。

创建命中等价项时只返回已有入口，不转为修改；继续、更新或 Review 的目标不存在时停止，不自动创建。
