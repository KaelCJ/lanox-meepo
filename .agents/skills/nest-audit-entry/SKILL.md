# Agent 入口内容审计

## 审计边界

- 每次审计当前工作空间内全部 `AGENTS.md` / `CLAUDE.md`；用户指定文件或目录时优先报告指定范围。
- 记录无法读取、明确排除和可能遗漏的范围，继续审计已发现入口。
- 全程只读，不修改入口、模板、Hook、Skill、Git index 或其他文件。

## 核心规则

1. **行为价值**：每条内容都应明确适用对象、触发条件、行为要求和作用范围；信息不足时列为待核实或改写，只有删除反事实成立时才建议删除。
2. **旁白检查**：背景感想、自我评价、工作心态、过程说明及其他叙述没有独立行为价值，且移除后不改变发现、行为和边界时，建议删除或压缩。
3. **重复检查**：宿主默认行为、常识、父入口已有规则或同一入口内的表达只有在当前生效链已由其他可达所有者保证同一行为，且删除反事实成立时才属于重复；标签本身不是删除依据。
4. **承载检查**：流程、方法论、动态事实、历史记录和操作教程应由 Skill、Rule、工作项或其他权威真源承载；迁移或删除前确认目标正文已建立、当前消费者可达，并保留首次相关动作前所需的最短路由。
5. **稳定性检查**：入口只保留跨任务稳定的约束，不保存日期化 proof、当前状态、版本快照或临时计划。
6. **准确性检查**：核实每项“必须”或“禁止”约束、路径及事实依据，并检查其与生效链上游是否存在无依据冲突，避免把建议、推断或单次问题升级为通用硬规则。
7. **精炼检查**：删除不影响行为边界的修饰、解释和重复句式，保留首次相关动作前必须知道的高损失边界及其最短完整表达。
8. **宿主对齐检查**：同目录双宿主入口的共享规则保持语义一致；差异仅在宿主发现、配置或工具能力确有当前依据时保留。

## 审计方法

清点单位是文件；审计判定单位是“宿主 × 目录作用域 × 触发场景”的上下文生效链。

1. 从用户明确的工作空间根或当前工作空间根发现全部入口，包含隐藏目录并排除 `.git`。
2. 读取 `.workspace-assistant/foundation/host-hooks/session-start-context.md`、`.codex/hooks.json` 和 `.claude/settings.json`，确定 Codex 与 Claude 的 SessionStart 上下文来源。
3. 对每个入口目录，先用哈希、差异或配对校验器归一同目录双宿主及祖先入口：共享正文只加载一次，宿主专属块和真实差异分别加载；无法可靠提取差异时才完整读取两份。再按两个宿主的发现语义重建生效链，识别每段正文的宿主、作用域和触发条件，不把同一祖先共享正文重复注入上下文。
4. 按触发条件读取入口路由的 Skill、Rule 与其他权威真源，重建对应上下文链；链上非入口内容只作为重复、冲突和承载判断基线。
5. 只有当前会话注入、宿主加载结果或已有运行证据能够证明的链才标为实际生效链；仅由配置、路径或正文声明推出的链标为声明链。
6. 将每段入口正文放回对应链应用核心规则，并做删除反事实：假设候选正文不存在，从新 Session 的首次相关动作开始核对 Agent 是否仍能及时找到唯一规则并保持原行为、安全和授权边界；任一项不能成立时不得建议先删，先给出承载或路由设计。比较双宿主共享正文时保留有依据的最小宿主差异。
7. 以入口文件和准确位置汇总问题，附带宿主、作用域、触发场景和上游依据；同一问题影响多条链时合并报告。

## 输出

- 第一行给出总体判断，随后只列已确认问题和必要的待核实项。
- 每个问题归为“删除、压缩、改写、迁移、待核实”，给出准确位置或最小原文、具体原因和最小处理建议。
- “删除”结论必须给出替代所有者、发现路径和删除反事实依据；不能证明时降级为“迁移”或“待核实”。
- 区分“内容有误”和“内容正确但过长或放错位置”。
- 仅在用户要求时提供完整改写稿。
